## 0. 要点

- **每个节点平等**（用户，2026-10-10）。装着 AgentSwitch 的每台机器是一个**节点**：Mac、没有界面的 Linux、iPhone。节点之间只有“有什么”的差别（有没有服务、有没有窗口、有没有 Clash、浏览器是窗口还是画面流），没有等级：同一套配对、同一张远程路由表、同样的限制；没有管理员节点，也不为无头节点另立规矩。有服务的节点既能被别的节点用，也能去用别的节点。
- **不需要新协议。** 远程接口（`app-v0.md` §2：自签证书加钉指纹、一次性配对码、设备令牌、私网来源限制、路由白名单）已经是“一个节点用另一个节点”的完整通道，手机今天就这样连 Mac。网状是把这条通道用在更多的两个节点之间；Linux 无头版是把同一套服务放到没有桌面的机器上。两件事互不依赖，可以分开做。
- **各管各的。** 谁能连、审批策略、配置的增删、跳过权限模式，每个节点都只在自己身上定，别的节点改不了——对谁都一样。Mac 在应用里定，Linux 在它的命令行里定（§4.3）。
- **连接由节点的服务持有**（建议，§10 第 2 条）。Mac 的主窗口、命令行、网页控制台都只连本机的服务，由服务去连别的节点；这样没有界面的节点和别的节点一样能用别人。手机没有服务，照旧自己直连。
- **不留痕。** 在哪个节点上开的会话，就是那个节点上 agent 自己的会话，写在 agent 自己的文件里；用它的一方除了这次配对（地址、证书、令牌、网关公钥）什么都不存。删掉配对，不剩东西；卸载 Linux 无头版，各 agent 的登录、配置、会话原样留着，照常用它们自己的命令行接着干。
- **节点报告自己有什么**（§3），界面只显示有的。

## 1. 节点与连接

**节点**是一份装好的 AgentSwitch，有自己的证书和指纹（就是今天远程口的那张）。

| 节点 | 服务（agent 在这里跑） | 界面 |
|---|---|---|
| Mac | 有 | 主窗口、菜单栏、命令行 |
| Linux 无头 | 有 | 命令行 |
| iPhone | 没有 | 应用 |

用户说的“linux 无头客户端”就是第二行：没有窗口，其余和 Mac 节点一样。

一次使用里有两个角色：**被用的一方**（下文仍叫主机）和**用的一方**（使用端）。有服务的节点两个角色都能当；手机没有服务，只能当使用端——这是它“有什么”的差别，不是规则不同。

**连接**是两个节点配一次对。两边都有服务时是**互通**的：一次配对，两个方向，每个方向可以单独关（§2.2）。

```
iPhone ───▶ MacBook ◀───▶ Mac mini
   │           ▲
   │           ▼
   └───▶ Linux 无头节点               ◀──▶ 互通      ──▶ 手机只有“用”这一个方向
```

## 2. 一次配对：两个方向、权限、存放、删除

### 2.1 沿用，不改

被用的一方出一个 8 位配对码（5 分钟、用一次、错 5 次作废），另一方凭码换设备令牌，钉住对方证书的指纹；令牌在被用的一方只存哈希，可单独吊销，吊销同时切断开着的流。来源网段限制、路由白名单、每个远程写请求记一行日志，都照旧。

由此是**逐对授权**：谁能用谁，以各节点自己的设备列表为准。

### 2.2 配对怎么交到另一边手里

配对载荷（`agentswitch://pair?p=…`）里已经有名称、端口、**证书指纹**、配对码、地址和网关公钥。交付方式有三种，差别在指纹从哪来：

| 方式 | 指纹 | 用在 |
|---|---|---|
| 二维码 | 在载荷里 | 手机扫 Mac 的屏幕；手机扫 SSH 窗口里用字符画出的码（§4.3） |
| 配对链接，粘贴 | 在载荷里 | 两台电脑之间（Mac 的设置里粘贴，或 `agentswitch nodes add <链接>`）；手机上粘贴（已有） |
| 只输 8 位码 | **没有** | 兜底。只凭码钉不住证书（中间可以有人），所以两边各显示一段指纹，人比对一致才继续——演示页的第 3 步就是这个 |

二维码和链接走的都是用户自己看得见的通道（屏幕、SSH、通用剪贴板），不需要比对。能用前两种就不出现第三种。

**一次配对，两个方向。** 出码的一方 A、输码的一方 B 都有服务时，B 兑换配对码的同时把自己的一份配对载荷附在请求里（`POST /pair` 多一个可选的 `back`：B 刚为这次出的一次性码、指纹、地址、网关公钥）；A 在自己这边确认（Mac 上是一张卡，命令行里是一句 `y/n`），再去 B 兑换。结果是两条设备记录：A 的设备表里有 B，B 的设备表里有 A。两个方向互不牵连，关掉一个另一个照旧。只想单向时，B 不附这一份，或 A 不确认。手机没有服务，自然只有它用别人这一个方向。

### 2.3 权限：对谁都一样

- `devices.platform` 多两个取值：`macos`、`linux`（今天只有 `ios`；库里本来就是自由文本）。它只决定图标和说法。
- **不分档**：配了对的节点，不论是手机、Mac 还是 Linux，能用的就是同一张远程路由表，受同样的限制（不能选跳过权限模式、不能建删配置、不能指对方的本地路径当附件、不能改审批策略……`remoteCaller` 的那些检查）。按节点勾选“只给 Dispatch / 只给 Terminals”（演示页里的勾选框）等到要把机器借给别人用时再做。
- **跳过权限模式**对所有节点一个规矩：只能在节点本机选。Mac 的本机是应用，Linux 的本机是命令行（`agentswitch new --mode bypass`，§4.3）。不为无头节点另开口子。
- 还要定的一处：节点之间终端的**原样按键**（`POST /terminals/:id/write` 今天只在本机，§10）。

### 2.4 存什么、怎么删

- 每个方向上，用的一方存：对方的名称、地址、端口、证书、网关公钥、自己在对方那里的设备号，加一个令牌。手机已经这样存（`macs.json` 加钥匙串，按指纹区分）。电脑上放在 `$AGENTSWITCH_HOME/nodes/`（目录 0700、文件 0600）。
- **令牌是新的要保护的东西。** 拿到节点 B 的令牌就能在 B 上开终端，等于能以 B 的用户身份跑命令。手机上没有别的程序读得到它；电脑上有——这台电脑自己的 agent。所以 `nodes/` 要和 `local-token` 同级保护，放进受保护路径的禁读名单（`protected.ts` 的 `readDenied`）。否则节点 A 上的 agent 读到令牌就能去操作节点 B。
- **删除**：“移除这个节点”时，先请对方吊销自己（新路由 `DELETE /me`），再删本地的令牌和记录；互通的另一个方向一并问要不要关。今天手机的“移除”只删本地，对方的设备列表里会留下一条再也不会上线的设备。

## 3. 节点报告自己有什么

节点种类多了，用它的一方不能再假设“对面是一台 Mac”。加一个远程路由 `GET /node`：

```json
{"name":"build-box","kind":"linux","version":"…","home":"/home/dev",
 "has":["dispatch","terminals","profiles","browser"]}
```

- `kind`：`mac` | `linux`。使用端按它选图标和说法（今天手机上有一百来处写着 `Mac` 的文案，§5.1）。
- `home`：主机上的主目录。使用端拿它把路径缩成 `~/…`；手机今天只认 `/Users/<名字>`，Linux 的 `/home/<名字>`、`/root` 缩不了。
- `has`：这台主机有的东西。没有的页或栏目就不显示：`clash`（只有装了 Clash Verge 的 Mac）、`browser`、`update`（经 `/update` 安装新版，只有 Mac 应用）、`keyboard`（接受原样按键）。
- 老主机没有这个路由（404）时，使用端按“Mac，全都有”处理，和今天一样。

## 4. Linux 无头版

### 4.1 装的是什么、放在哪

Linux 无头节点就是少一个窗口的 Mac 节点：能被别的节点用，也能去用别的节点。组成与 Mac 应用包里的 `runtime` 相同：Node、daemon、Python、secret-gate。没有应用；应用替服务做的那些事交给一个小的看护进程，应用的界面由命令行顶替（§4.3）。

| 东西 | 位置 | 说明 |
|---|---|---|
| 程序 | `~/.local/share/agentswitch/runtime/<版本>/`，`current` 指向在用的 | 按架构各一份（x86_64、aarch64）。`node-pty` 没有 Linux 的预编译包，打包时按架构编好带上；Python 依赖锁（`python-requirements.txt`）今天只有 macOS 的 wheel 哈希，Linux 另出一份 |
| 命令 | `~/.local/bin/agentswitch` | 指向 `current` 里的启动脚本 |
| 状态 | `~/.agentswitch`（daemon 的默认位置）、`~/.secret-gate` | 这两个名字已经在各处的保护规则里（工作目录禁区、路由器的自保规则、浏览器规则），不用为 Linux 另加。不放 XDG 目录，正是为了不动这些规则 |
| 看护 | `~/.config/systemd/user/agentswitch.service` | 见 §4.2 |

全部在用户主目录里，装和卸都不需要 root。唯一要 root 的是把凭据网关放到独立账户下（§4.5），可选。

### 4.2 看护、更新、卸载

- **一个看护进程**：`agentswitch node run`，前台运行，日志到标准输出。它接过 Mac 应用今天替服务做的事（应用里的 `RuntimePlan`、`ChildEnvironment`、`Supervision`、`ProcessSupervisor`）：
  - 先起凭据网关、探到它就绪，再起 daemon；同一个状态目录只许一份在跑（锁文件）；上次崩溃留下的进程先清掉。
  - 给 daemon 的环境变量照应用的那张表：`AGENTSWITCH_HOME`、两个端口、`AGENTSWITCH_REMOTE=1` 与名称、`AGENTSWITCH_EXECUTORS=real`、`SECRET_GATE_HOME` / `_BIN` / `_PROXY`（独立账户时再加 `_PUBLIC`、`_CA`）、四个 agent 的 `*_BIN`。别的一概不继承。
  - **`PATH` 取登录 shell 的**（应用是 `$SHELL -lic` 问出来再并上几个常见目录）。systemd 用户服务的环境里没有用户的 `PATH`，不这样做就找不到装在 `~/.local/bin`、`~/.opencode/bin` 里的 agent。
  - 每 3 秒探一次，连着不应就重启，重启间隔从 1 秒翻倍到 60 秒；设置改了需要重启时（`PUT /settings/models` 回 `restartRequired`）重启 daemon；退出时先停 daemon 再停网关。
  - 不需要的：防睡眠、Bonjour、菜单栏卡片、登录项。
- **systemd 用户服务**只负责把这个看护进程开机拉起、退出时重启：`agentswitch service install | uninstall | status | logs`。要 `loginctl enable-linger` 才能在没人登录时运行（在 SSH 会话里要不要 sudo 没验证，§8）。没有 systemd 的地方（容器、tmux）直接跑 `agentswitch node run`。
- **更新**：`agentswitch update <包>`——校验、解到 `runtime/<新版本>/`、切 `current`、重启；起不来就切回去。从哪下载等 AgentSwitch 自己有发布渠道再说，v0 是把包拷过去。主机的 `/update` 路由只认 `AgentSwitch.app`，Linux 上 `has` 里没有 `update`，手机上不显示那一栏。
- **卸载**：`agentswitch uninstall` 删程序、命令、systemd 单元；状态目录问过再删；各 agent 自己的目录（`~/.claude`、`~/.codex`、`~/.local/share/opencode`、`~/.pi`）一概不碰。

### 4.3 命令行：无头节点的界面

命令行之于 Linux 节点，相当于主窗口加设置之于 Mac：**管自己、用自己的 agent、用别的节点**，三件事都在这里。它们大多只是本地接口的外壳（命令行用 `local-token`，和现在的子命令一样），所以在 Mac 的终端里也一样能用。调度那一半今天已经有了（`task`、`tasks`、`watch`、`approve`、`answer`、`threads`……）。

| 命令 | 做什么 | 背后 |
|---|---|---|
| `agentswitch pair` | 出一个配对码：在终端里画二维码，下面是链接、分组显示的指纹、地址、剩余时间；等到有设备配上就打印是谁。`--link`、`--json` 只出文字 | `POST /pairing`，再看 `GET /devices` |
| `agentswitch devices`、`devices revoke <设备>` | 列出设备（在不在线、上次见到），吊销 | `GET` / `DELETE /devices` |
| `agentswitch node`、`node name "<名称>"` | 名称、端口、指纹、地址；起名 | `GET /remote/info`；起名是新的设置（今天只有环境变量 `AGENTSWITCH_REMOTE_NAME`；10-04 那台机器回退出来的是一长串带机器型号的主机名） |
| `agentswitch doctor` | 环境检查：四个 agent 找到没有、版本、登录没有；`node-pty`、凭据网关、Tailscale、浏览器要的系统库 | 应用里的环境检查搬到服务这边 |
| `agentswitch profiles …` | 列出、新建、删除、改颜色；`profiles login <配置>` 就在当前这个 SSH 窗口里起那个 agent 的登录 | `/profiles…`（建删只在本机，正好） |
| `agentswitch policy …`、`models …`、`keys …` | 审批策略（已有）、路由与默认模型、网关密钥对 | 已有的本地接口与 `secret-gate keys` |
| `agentswitch mcp`、`skills`、`context` | 调度用的 MCP、skill 注册表与环境说明。今天只能看（`context init` 除外），写入要补 | Mac 上在设置的 Dispatch 那一组；这些路由不对远程开放，无头节点上只能在这里改 |
| `agentswitch service …`、`update`、`uninstall`、`logs` | §4.2 | — |
| `agentswitch terminals`、`new`、`resume`、`attach <终端>` | 列出、新建、恢复终端；`attach` 把服务持有的终端接到当前这个真终端上（画面、按键、尺寸），退出只是松手，终端照跑。跳过权限模式在 `new` 这里选 | `/terminals…`；`attach` 用画面流加 `/write`。在 Mac 上同样有用：在 iTerm 里接上 AgentSwitch 开的会话 |
| `agentswitch nodes`、`nodes add <链接>`、`nodes remove <节点>` | 这个节点连着的别的节点：列出（通不通、有几个在等你）、用配对链接加一个、移除 | `/nodes…`（新，§5.2） |
| 任意命令加 `--on <节点>` | 对别的节点做同一件事：`agentswitch --on mini terminals`、`--on mini attach …`、`--on mini task "…"` | 经本机服务转给那个节点（§5.2） |

二维码太密时少带地址（连上后 `/addresses` 会补全）。`pair` 是 Linux 主机的信任起点：能 SSH 上去的人才能让一台设备配进来，这一点不变。

| 部件 | 在 Linux 上 | 状况 |

| daemon（任务、路由、接口、远程口、证书） | 原样 | 10-04 验证过，没改代码 |

| 浏览器 | Camoufox 有 Linux 版，代码在非 Mac 上本来就按无头启动；使用端看画面流，就是手机今天的看法。要装系统库 | 没试 |
| 调度执行器的浏览器 | 是经网关的 Playwright MCP 起的 Chrome，机器上要有 Chrome 或 Chromium；清理 Chrome 签名副本那一步只在 Mac 上有，别处自动跳过 | 没试 |
| Clash Integration | 是把订阅交给 Clash Verge（桌面应用） | 无头节点没有这一页；配置自己的代理不受影响 |
| Agents 页（安装、更新、换版本） | 在 Mac 应用里实现 | 没有；agent 自己装，`doctor` 报告找到了什么（`agents-v0.md` §9 已这样写） |
| 局域网发现（Bonjour） | 由 Mac 应用发布 | 没有；靠配对载荷里的地址和 `/addresses`，和今天手机离开局域网时一样 |

| 保护规则 | `~/.agentswitch`、`~/.secret-gate` 按名字已覆盖；`Library`、数据卷那几条是 Mac 的 | 要逐条在 Linux 上试（§8） |
| 文案 | `on this Mac`、`chosen on the Mac` 这类写死的句子 | 要改成不分主机种类的说法 |

### 4.5 凭据网关放在哪个账户下

Mac 上网关跑在独立的服务账户里（`gate-service-v0.md`）：登录用户的进程——包括 agent——在文件层面读不到私钥。Linux 上有两档：

- **同用户**：网关由看护进程以登录用户身份起，密钥在 `~/.secret-gate`（0700）。agent 读不到它只靠各家的禁读规则，这是 Mac 在 2026-09-27 之前的状态。不需要 root。
- **独立账户**：`sudo agentswitch gate system-install` 建一个不能登录的系统用户，网关作为 systemd 系统服务在它名下运行，目录与接口照 `gate-service-v0.md`（`/var/lib/agentswitch/gate` 0700、`gate-public` 里是 CA 证书、公钥和按对端 uid 放行的套接字）。要一次 root，与 Mac 上输一次管理员密码相当。

建议：两档都做，安装时问；有 sudo 就用独立账户。服务器上 agent 更常以自动或跳过权限的方式跑，文件层面的隔离比在 Mac 上更要紧。先后上可以先同用户（已验证），独立账户作为后一步。

### 4.6 在没有浏览器的机器上登录 agent

AgentSwitch 不搬运登录：每台主机上的 agent 各自登录，凭据留在 agent 自己的地方。按各家的说明，无头机器上都能在终端里完成（打印网址，在别的设备上登录，把码贴回来；或填密钥）。配合已有的“没登录的配置开终端就从登录开始”，在手机或 Mac 上新建一个终端就能把登录做完：终端里出网址，在手边的设备上打开，登录后把码贴回终端。没验证（§8）。

### 4.7 地址与监听

- **地址**：今天配对载荷和 `/addresses` 的 `lan` 把 Docker 网桥也列了进去（10-04 那台机器上 11 个里 10 个是）。Linux 上按网卡过滤（`docker0`、`br-*`、`veth*`、`virbr*`），默认路由所在的网卡排最前。
- **来源限制照旧**：只接受私网、链路本地、Tailscale 网段。所以**只有公网地址的云主机必须走 Tailscale 或别的私网**，这是要的效果（没有公网可达面）。这类机器上监听最好只绑 Tailscale 的地址（今天是 `::` 全绑、连上来再按来源掐断）：`agentswitch node listen tailscale | private | all`。
- **不想装 Tailscale 时**：`ssh -L 4713:127.0.0.1:4713 <主机>`，使用端连本机的 4713。证书照样钉着指纹，来源是回环地址，在允许范围内；主机这边不用改，使用端要能手填一个地址。只对电脑上的使用端有用。
- 使用端连主机不走任何代理（系统代理、Clash、凭据网关的代理都不走）。

## 5. 使用端

### 5.1 iPhone：几个节点同时在线

今天的样子（代码里看到的）：可以配多台，同一时间只连一台；主机按证书指纹区分；整个应用只有一个 `AppModel`，里面一条连接、一个接口客户端，界面有 61 处直接读它；切换主机时停掉连接、清空取来的一切再重连。连接用的零件（钉指纹的会话、选地址、接口客户端）本来就是按主机传参的，不是全局的。Dispatch 标题里已经有一个切换主机的菜单（配了一台以上才出现）。任务、终端、会话、标签页的编号都只在各自主机内唯一，手机上的草稿、折叠状态、终端看法是按光秃秃的编号或路径存的。没有后台运行、没有推送、没有本地通知；实时活动只有一条，只在应用在前台时更新。

由此，分两步：

1. **Linux 节点先当“又一台”**。今天的切换就够用。要改的是：按 `GET /node` 换说法和图标（`Mac` 的文案有一百来处，标识符和 `macs.json` 这些内部名字不必动）、路径缩写用主机报的 `home`、没有的栏目不显示（`Mac App` 更新、Clash）、“移除”时请主机吊销自己。
2. **同时在线**。建议的形状是**按主机分开看、提醒汇总**，不合并列表：
   - 每台配了对的主机各有一个轻的看守：一条连接，定时问一个摘要。摘要用 `GET /live`——Mac 菜单栏卡片今天每秒问的那个，内容是进行中的任务、在干活或等你的终端、可以直接回答的请求——把它放进远程路由表（只读，里面的东西手机本来都读得到）。
   - 四个页仍然只显示“当前主机”，切换菜单从 Dispatch 的标题扩到每一页，菜单里每台主机带状态（有几个在等你）。
   - 等你的东西跨主机汇总：角标、提示音、实时活动都算上所有主机；每一行带主机名，点进去先切到那台主机再打开。实时活动的链接要带上主机（今天是 `agentswitch://terminal/<编号>`，没有主机）。
   - 手机上按编号、路径存的东西改成按“主机指纹 + 编号”存。
   - 不合并列表的理由：没有一个列表元素带着主机，编号会撞，文件夹树的键是各主机自己的路径；合并要动的面比分开看大得多，而“哪台在等我”这件最要紧的事，汇总提醒已经给了。
   - 应用在后台时仍然什么都收不到（没有推送），和今天一样。

### 5.2 Mac 主窗口：用别的节点

今天的样子（代码里看到的）：主窗口只有一个客户端 `DaemonClient`，地址写死 `http://127.0.0.1:<端口>`，凭 `local-token`；应用里没有钉证书的代码，也没有“主机”这个概念。只有 Dispatch 页隔着接口（`DispatchService`，它的注释里就写着留给“远处的 Mac”），Browser 页隔了一半，Terminals、Clash、设置、菜单栏卡片都直接拿这个客户端。好在两点：各页拿客户端的方式是“每次现取”，换一个来源就都跟着换；远程口对放行的路由是原样转给本地接口的，路径和数据形状完全相同——**同一个客户端、同一批请求就能对着别的节点用**，不必另写一套——差的只是这些请求怎么送到那个节点（见下面“连接怎么做”）。

- **入口**：主窗口左上角的节点菜单（演示页第 2 节）：`This Mac` 加配过对的节点，各带状态；换节点时用“换台”那段转场（`dispatch-v0.md` 里说过，这个转场就是留给它的）。
- **配对**：`Settings › Nodes`，取代现在的 `Devices`。出码（二维码与链接，已有）和粘贴别的节点的链接都在这里。每个配过对的节点一行，两个方向各一个开关：这台 Mac 用它、它用这台 Mac；手机只有后一个。
- **每一页连别的主机时**：

| 页 | 已经有远程路由的 | 不能照搬的 |
|---|---|---|
| Dispatch | 对话、任务、审批与提问、话题、上传、搜索 | 设置里 Dispatch 那一组（记忆、平台经验、MCP、skill、路由日志）不在远程表里，连别的主机时不显示：那是主机自己的管理 |
| Terminals | 列表、新建、恢复、画面流、简略视图、回复、权限卡、模型与档位、git 状态 | 终端屏幕上打字走的是 `/write`（每 4 毫秒一批原样按键），不在远程表里：不放开的话真终端只能看，回话只能用简略视图的回复框（§10 第 5 条）。拖进来的文件、回复里的附件今天给的是本机路径，改成上传；选文件夹用的是本机的面板，改成从主机用过的文件夹里选或手输；⌘ 点路径是在本机磁盘上找，连别的主机时不做 |
| Browser | Mac 上本来就有两种看法：真窗口，和画面流（主机报 `windows: false` 时用，与手机相同）。连别的主机一律用画面流，是现成的 | `Show Window`、静态预览、引擎安装不在远程表里，也不该在 |
| Clash | 路由都在远程表里 | 对面有 `clash` 才显示；“交给 Clash Verge”那一步只能在对面那台 Mac 上点 |
| Settings | — | 仍然是这台 Mac 自己的，`Devices` 换成 `Nodes`；配置的建、删、改颜色、模型设置、审批策略都是主机本机的事 |

- **连接怎么做**（建议经本机服务；另一种做法见 §10 第 2 条）：本机的 daemon 保管这个节点连着的别的节点（§2.4），并在本机接口上多一段 `/nodes/<节点>/…`，把请求原样转给那个节点的远程口——钉着配对时拿到的证书，带设备令牌，事件流和画面流也照转；选地址（局域网、Tailscale）、断了重连都在这里做一次。主窗口这边，`DaemonClient` 已经有“给一组路由加前缀”的做法（切到某个配置自己的浏览器就是这样），选了别的节点就是所有请求多一段前缀。命令行的 `--on`、网页控制台用的是同一段。它**只在本机接口上，不进远程路由表**：配对进来的节点不能借这个节点去用第三个节点（那是中转，§7）。本机专有的事（看护、配对与设备、各项设置）不加前缀。
- **给别的节点造密文**用那个节点的公钥。主窗口今天的“新建密文”用的是本机网关（`GateCLI`）；对别的节点时由内置的 secret-gate 对指定公钥封装（要给它加一个参数），不在 Swift 里做密码学。
- **顺手要改的小处**：
  - 屏幕编号是 `mac-<随机>`，服务把别的以 `mac` 开头的编号当成“这台 Mac 自己的另一块屏、已经松手”。别的 Mac 的屏幕会被这样误读，经转发来的请求要带上是哪个节点的屏。
  - 远程口对表外的路由回带 `error` 的 404，应用今天把这种 404 读成“终端没了”；要分开。
  - 路径缩写、字体：路径按主机报的 `home` 缩；终端样式里的字体在本机找不到时用默认的。
- **跨节点的提醒**：菜单栏卡片今天只显示本机的。连着别的节点时把它们等你的东西也列进来（各带节点名）；服务替它去问各节点的 `GET /live`，卡片还是只问本机一次。

### 5.3 命令行

没有窗口的节点靠它当使用端，内容在 §4.3：`terminals`、`attach`、调度的那些子命令，加 `--on <节点>`。没有浏览器页（终端里看不了画面流）——这是“有什么”的差别。Mac 上同一套命令也能用。

## 6. 安全边界的变化

实现时写进 `packages/secret-gate/BOUNDARY.md` 和 `app-v0.md` §6：

1. **配对的设备等于能在主机上以用户身份跑命令**（经终端里的 agent）。对手机一直如此；现在电脑也能当使用端，所以电脑上保存的别的主机的令牌要防这台电脑自己的 agent（§2.4）。
2. **密文不跨主机。** 每台主机有自己的网关和密钥对，使用端给哪台主机发密文就用哪台的公钥；A 的密文在 B 解不开。手机存的密文已经按主机指纹标记，只在给它造的那台主机上列出。凭据不随连接扩散。
3. **服务保管别的节点的令牌并替本机的界面转发**（若按 §10 第 2 条的建议）：`/nodes/…` 只在本机接口上，凭 `local-token`；不进远程路由表，所以没有中转。转发只发往已配对的节点、钉着它的证书，目的地不由请求决定。没有跨节点调度。
4. **平等也意味着风险对称**：互通的两个节点，一个被攻破，另一个就能被它用。放在外面的机器和手边的 Mac 配对时，可以只留“Mac 用它”这一个方向（§2.2）；每个方向随时能单独关。
5. **只输配对码时必须比对指纹**（§2.2）。
6. **各管各的**：远程接口不加管理路由，对哪种节点都一样；无头节点上 `pair`、吊销、策略、配置的建删都要先 SSH 登上那台机器。
7. **公网机器**：来源限制不变；监听最好只绑私网地址（§4.7）。
8. **Linux 上网关的隔离档位**要写清楚：同用户档下私钥只靠禁读规则挡着（§4.5）。
9. **原样按键**：定了以后记一条（§10）。

## 7. 不做（除非 §10 另有决定）

- 信任组：加入一次就和网里所有节点互通。它要一个“谁能放新节点进来”的答案；节点平等的话就是谁都能放，一个节点被攻破等于全网被攻破（§10 第 1 条）。
- 中转：手机够不着的节点，经另一个节点转过去。走 Tailscale 或别的私网；电脑上还可以用 SSH 隧道（§4.7）。连接放在服务里以后这件事技术上不难（把 `/nodes/…` 对配对进来的节点放开），难的是信任：能连中间那个节点的，就都能用它连着的节点（§10 第 4 条）。
- 跨节点调度（A 的调度把任务派给 B 的 agent）：密文绑在各自网关的公钥上，另一个节点解不开；“使用对方的 Dispatch”指的是直接对 B 说话。
- 把会话从一个节点搬到另一个：会话是那个节点上 agent 自己的文件，换机器接着干用 agent 自己的办法和 git。
- 在 Linux 上替你装 agent、管版本（Agents 页）；Linux 上的 Clash。
- 按节点分权限档（§2.3）。

## 10. 待拍板

**已定（用户，2026-10-10）：每个节点平等，无头节点和别的机器一样。** 由它直接定下来的：

- Linux 无头节点两个角色都当，命令行使用端进入这一轮（原来建议以后再说）。
- 没有管理员节点；每个节点只在自己身上管自己，无头节点就是 SSH 加命令行。
- 跳过权限模式不为无头节点另开开关，规矩和 Mac 一样：只在节点本机选。

还要定的：

1. **网是一对一对配出来的**（建议：谁和谁配过才通，沿用现有机制），还是**加入一次就全通**（信任组）。后者省事，但节点平等时任何一个节点都能放新节点进来，一个被攻破就是全部。
2. **连接由谁持有**，两种做法：
   - **节点的服务**（建议）：本机 daemon 保管别的节点的令牌，在本机接口上转发；主窗口、命令行、网页控制台共用一份，没有窗口的节点和别的节点做法完全一样。代价是 daemon 多了一块出站的面。
   - **界面直连**：主窗口、命令行各自去连，和手机一样，daemon 不出门。代价是同一套连接逻辑要有三份（iPhone 已有的、Mac 应用里一份、命令行里一份）。第二稿最初建议的是这个；节点平等以后每种节点都得能当使用端，我改为建议前一种。
3. **两个有服务的节点配对，默认互通**（建议，可以只选单向），还是默认单向、要互通再配一次。
4. **中转**：手机只够得着 Mac 时，要不要经 Mac 去用 Linux 节点。建议先不做；要做的话是每条连接上一个默认关着的开关（“可以经我去用它”），由中间那个节点的主人打开。
5. **节点之间的键盘**：建议远程口接受原样按键（`/write`），每个节点上一个开关，默认开。理由：Mac 的终端屏幕和命令行的 `attach` 都靠它打字，不放开就只能看；而文字入口今天已经能打任何命令再回车，只给文字并不减少配对的节点能做的事。实现时要逐个 agent 确认没有哪个按键能把它切进跳过权限模式。还是照手机，只给文字和指定按键（演示页当初的建议）。
6. **Linux 上的凭据网关**：两档都做、安装时问、有 sudo 就用独立账户（建议）；还是只做同用户。
7. **界面上“按节点分开看、提醒汇总”**（建议）；还是合并成一张列表。
8. **安装形态**：一个按架构的压缩包加安装脚本、systemd 用户服务（建议）。以后可以加“从 Mac 上经 SSH 装到一台 Linux 并顺手配对”，要不要。
9. **先后**（§9）。
