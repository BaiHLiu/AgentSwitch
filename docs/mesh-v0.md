## 0. 要点

- **不需要新协议。** 远程接口（`app-v0.md` §2：自签证书加钉指纹、一次性配对码、设备令牌、私网来源限制、路由白名单）已经是“一个使用端连一台主机”的完整通道，手机今天就这样连 Mac。网状是把这条通道用在更多的两端之间；Linux 无头版是把同一套服务放到没有桌面的机器上。两件事互不依赖，可以分开做。
- **主机说了算，管理只在主机本机。** 配对出去的设备只能用远程路由表里的那些；谁能连、审批策略、配置的增删、跳过权限模式，都只在主机自己身上定。Mac 上“本机”是应用；Linux 上“本机”是经 SSH 登录后的命令行（§4.3）。远程接口不为无头主机多开管理路由。
- **服务不去连别的主机**（建议；另一种做法见 §10 第 5 条）。连别的主机这件事只由界面做（iPhone 应用、Mac 应用的主窗口、以后的命令行），daemon 不去拨别的主机的远程口。跨主机调度也因此不在这一稿里（§7）。
- **不留痕。** 在主机上开的会话就是那台主机上 agent 自己的会话，写在 agent 自己的文件里；使用端除了这次配对（地址、指纹、令牌、网关公钥）什么都不存。删掉配对，使用端上不剩东西；卸载 Linux 无头版，各 agent 的登录、配置、会话原样留着，照常用它们自己的命令行接着干。
- **主机不再都一样。** Linux 主机没有 Clash 页，浏览器只有画面流，更新方式也不同。主机要告诉使用端自己有什么（§3），使用端只显示有的。

## 1. 角色与边

- **主机**：跑服务（daemon 加凭据网关）、agent 在它上面运行的机器。今天只有 Mac 应用；加 Linux 无头版。
- **使用端**：连到主机，用它的 Dispatch、Terminals、Browser 的一方。今天只有 iPhone；加 Mac 应用的主窗口，以后可以有命令行。
- 一条**边**是“使用端 → 主机”的一次配对，有方向。“网”就是若干条边：

```
iPhone ───────────▶ MacBook ◀──────────▶ Mac mini      两台 Mac 互相使用 = 两条边，各配一次
   │                   │
   └───────────▶ Linux 主机 ◀───┘                      Linux 只当主机
```

一台 Mac 两种角色都是：它的服务是主机，它的主窗口是使用端。Linux 无头版先只当主机——“无头客户端”这个说法，这里取的意思是“没有界面的那一版 AgentSwitch”。它要不要也当使用端（在 Linux 的命令行里看别的主机的终端）见 §5.3，建议以后再说。

## 2. 一条边：配对、权限、删除

### 2.1 沿用，不改

主机出一个 8 位配对码（5 分钟、用一次、错 5 次作废），使用端凭码换设备令牌，钉住主机证书的指纹；令牌在主机上只存哈希，可单独吊销，吊销同时切断开着的流。来源网段限制、路由白名单、每个远程写请求记一行日志，都照旧。

由此是**逐对授权**：谁能用谁，以各主机自己的设备列表为准。“信任组”（一组机器互相全通）要另一套密钥分发，不做。

### 2.2 配对怎么交到使用端手里

配对载荷（`agentswitch://pair?p=…`）里已经有名称、端口、**证书指纹**、配对码、地址和网关公钥。交付方式有三种，差别在指纹从哪来：

| 方式 | 指纹 | 用在 |
|---|---|---|
| 二维码 | 在载荷里 | 手机扫 Mac 的屏幕；手机扫 SSH 窗口里用字符画出的码（§4.3） |
| 配对链接，粘贴 | 在载荷里 | Mac 主窗口配别的主机；手机上粘贴（已有） |
| 只输 8 位码 | **没有** | 兜底。只凭码钉不住证书（中间可以有人），所以两边各显示一段指纹，人比对一致才继续——演示页的第 3 步就是这个 |

二维码和链接走的都是用户自己看得见的通道（屏幕、SSH、通用剪贴板），不需要比对。能用前两种就不出现第三种。

### 2.3 设备与权限

- `devices.platform` 多两个取值：`macos`、`linux`（今天只有 `ios`；库里本来就是自由文本）。
- **v0 不分档**：配了对的设备，不论是手机还是 Mac，能用的就是同一张远程路由表，受同样的限制（不能选跳过权限模式、不能建删配置、不能指主机上的本地路径当附件、不能改审批策略……`remoteCaller` 的那些检查）。按设备勾选“只给 Dispatch / 只给 Terminals”（演示页里的勾选框）等到要把主机借给别人用时再做。
- 两处要单独定，见 §10：Mac 当使用端时终端的**原样按键**（`POST /terminals/:id/write` 今天只在本机），和无头主机上的**跳过权限模式**。

### 2.4 使用端存什么、怎么删

- 每条边使用端存：名称、地址、端口、指纹、网关公钥、设备号，加一个令牌。手机已经这样存（`macs.json` 加钥匙串，按指纹区分主机）。
- **令牌是新的要保护的东西。** 拿到主机 B 的令牌就能在 B 上开终端，等于能以 B 的用户身份跑命令。手机上没有别的程序读得到它；电脑上有——这台电脑自己的 agent。所以 Mac 当使用端时，别的主机的令牌要和 `local-token` 同级保护：一个 0600 的文件，放进受保护路径的禁读名单（`protected.ts` 的 `readDenied`）。否则主机 A 上的 agent 读到令牌就能去操作主机 B。（Mac 应用今天不往钥匙串里存东西，`local-token` 也是文件；和它用同一种保护，不另起一套。）
- **删除**：在使用端“移除这台主机”时，先请主机吊销自己这台设备（新路由 `DELETE /me`），再删本地的令牌和记录。今天手机的“移除”只删本地，主机的设备列表里会留下一条再也不会上线的设备。

## 3. 主机告诉使用端自己有什么

主机种类多了，使用端不能再假设“对面是一台 Mac”。加一个远程路由 `GET /host`：

```json
{"name":"build-box","kind":"linux","version":"…","home":"/home/dev",
 "has":["dispatch","terminals","profiles","browser"]}
```

- `kind`：`mac` | `linux`。使用端按它选图标和说法（今天手机上有一百来处写着 `Mac` 的文案，§5.1）。
- `home`：主机上的主目录。使用端拿它把路径缩成 `~/…`；手机今天只认 `/Users/<名字>`，Linux 的 `/home/<名字>`、`/root` 缩不了。
- `has`：这台主机有的东西。没有的页或栏目就不显示：`clash`（只有装了 Clash Verge 的 Mac）、`browser`、`update`（经 `/update` 安装新版，只有 Mac 应用）、`keyboard`（接受原样按键）。
- 老主机没有这个路由（404）时，使用端按“Mac，全都有”处理，和今天一样。

## 4. Linux 无头版

### 4.1 装的是什么、放在哪

组成与 Mac 应用包里的 `runtime` 相同：Node、daemon、Python、secret-gate。没有菜单栏应用；它替服务做的那些事，一部分交给一个小的看护进程，一部分交给命令行（§4.3）。

| 东西 | 位置 | 说明 |
|---|---|---|
| 程序 | `~/.local/share/agentswitch/runtime/<版本>/`，`current` 指向在用的 | 按架构各一份（x86_64、aarch64）。`node-pty` 没有 Linux 的预编译包，打包时按架构编好带上；Python 依赖锁（`python-requirements.txt`）今天只有 macOS 的 wheel 哈希，Linux 另出一份 |
| 命令 | `~/.local/bin/agentswitch` | 指向 `current` 里的启动脚本 |
| 状态 | `~/.agentswitch`（daemon 的默认位置）、`~/.secret-gate` | 这两个名字已经在各处的保护规则里（工作目录禁区、路由器的自保规则、浏览器规则），不用为 Linux 另加。不放 XDG 目录，正是为了不动这些规则 |
| 看护 | `~/.config/systemd/user/agentswitch.service` | 见 §4.2 |

全部在用户主目录里，装和卸都不需要 root。唯一要 root 的是把凭据网关放到独立账户下（§4.5），可选。

### 4.2 看护、更新、卸载

- **一个看护进程**：`agentswitch host run`，前台运行，日志到标准输出。它接过 Mac 应用今天替服务做的事（应用里的 `RuntimePlan`、`ChildEnvironment`、`Supervision`、`ProcessSupervisor`）：
  - 先起凭据网关、探到它就绪，再起 daemon；同一个状态目录只许一份在跑（锁文件）；上次崩溃留下的进程先清掉。
  - 给 daemon 的环境变量照应用的那张表：`AGENTSWITCH_HOME`、两个端口、`AGENTSWITCH_REMOTE=1` 与名称、`AGENTSWITCH_EXECUTORS=real`、`SECRET_GATE_HOME` / `_BIN` / `_PROXY`（独立账户时再加 `_PUBLIC`、`_CA`）、四个 agent 的 `*_BIN`。别的一概不继承。
  - **`PATH` 取登录 shell 的**（应用是 `$SHELL -lic` 问出来再并上几个常见目录）。systemd 用户服务的环境里没有用户的 `PATH`，不这样做就找不到装在 `~/.local/bin`、`~/.opencode/bin` 里的 agent。
  - 每 3 秒探一次，连着不应就重启，重启间隔从 1 秒翻倍到 60 秒；设置改了需要重启时（`PUT /settings/models` 回 `restartRequired`）重启 daemon；退出时先停 daemon 再停网关。
  - 不需要的：防睡眠、Bonjour、菜单栏卡片、登录项。
- **systemd 用户服务**只负责把这个看护进程开机拉起、退出时重启：`agentswitch service install | uninstall | status | logs`。要 `loginctl enable-linger` 才能在没人登录时运行（在 SSH 会话里要不要 sudo 没验证，§8）。没有 systemd 的地方（容器、tmux）直接跑 `agentswitch host run`。
- **更新**：`agentswitch update <包>`——校验、解到 `runtime/<新版本>/`、切 `current`、重启；起不来就切回去。从哪下载等 AgentSwitch 自己有发布渠道再说，v0 是把包拷过去。主机的 `/update` 路由只认 `AgentSwitch.app`，Linux 上 `has` 里没有 `update`，手机上不显示那一栏。
- **卸载**：`agentswitch uninstall` 删程序、命令、systemd 单元；状态目录问过再删；各 agent 自己的目录（`~/.claude`、`~/.codex`、`~/.local/share/opencode`、`~/.pi`）一概不碰。

### 4.3 命令行：无头主机的管理面

Mac 应用的设置里能做的事，Linux 上都在这里做。它们大多只是本地接口的外壳（本地接口已有，命令行用 `local-token`，和现在的子命令一样），所以在 Mac 的终端里也能用。

| 命令 | 做什么 | 背后 |
|---|---|---|
| `agentswitch pair` | 出一个配对码：在终端里画二维码，下面是链接、分组显示的指纹、地址、剩余时间；等到有设备配上就打印是谁。`--link`、`--json` 只出文字 | `POST /pairing`，再看 `GET /devices` |
| `agentswitch devices`、`devices revoke <设备>` | 列出设备（在不在线、上次见到），吊销 | `GET` / `DELETE /devices` |
| `agentswitch host`、`host name "<名称>"` | 名称、端口、指纹、地址；起名 | `GET /remote/info`；起名是新的设置（今天只有环境变量 `AGENTSWITCH_REMOTE_NAME`；10-04 那台机器回退出来的是一长串带机器型号的主机名） |
| `agentswitch doctor` | 环境检查：四个 agent 找到没有、版本、登录没有；`node-pty`、凭据网关、Tailscale、浏览器要的系统库 | 应用里的环境检查搬到服务这边 |
| `agentswitch profiles …` | 列出、新建、删除、改颜色；`profiles login <配置>` 就在当前这个 SSH 窗口里起那个 agent 的登录 | `/profiles…`（建删只在本机，正好） |
| `agentswitch policy …`、`models …`、`keys …` | 审批策略（已有）、路由与默认模型、网关密钥对 | 已有的本地接口与 `secret-gate keys` |
| `agentswitch mcp`、`skills`、`context` | 调度用的 MCP、skill 注册表与环境说明。今天只能看（`context init` 除外），写入要补 | Mac 上在设置的 Dispatch 那一组；这些路由不对远程开放，无头主机上只能在这里改 |
| `agentswitch service …`、`update`、`uninstall`、`logs` | §4.2 | — |

二维码太密时少带地址（连上后 `/addresses` 会补全）。`pair` 是 Linux 主机的信任起点：能 SSH 上去的人才能让一台设备配进来，这一点不变。

| 部件 | 在 Linux 上 | 状况 |
|---|---|---|
| daemon（任务、路由、接口、远程口、证书） | 原样 | 10-04 验证过，没改代码 |
| 终端 | `node-pty` 要编译 | 10-04 验证过伪终端与远程流 |
| Claude Code | 官方有 `linux-x64`、`linux-arm64`（及 musl） | 没试。登录凭据在 Linux 上是配置目录里的文件（Mac 上在钥匙串）：配置各有各的目录，反而简单；但 Dispatch 执行器给每个线程一个私有配置目录，Mac 上靠 `CLAUDE_SECURESTORAGE_CONFIG_DIR=""` 留住钥匙串里的登录，Linux 上这招多半不成立，要另想 |
| Codex | 官方有 x86_64、aarch64 的 musl 版，自带 `bwrap` | 没试。Mac 上可以选 ChatGPT.app 自带的那一份，Linux 上没有这一项 |

| pi | npm 包，要 Node ≥ 22.19 | 没试 |

| 浏览器 | Camoufox 有 Linux 版，代码在非 Mac 上本来就按无头启动；使用端看画面流，就是手机今天的看法。要装系统库 | 没试 |
| 调度执行器的浏览器 | 是经网关的 Playwright MCP 起的 Chrome，机器上要有 Chrome 或 Chromium；清理 Chrome 签名副本那一步只在 Mac 上有，别处自动跳过 | 没试 |
| Clash Integration | 是把订阅交给 Clash Verge（桌面应用） | 无头主机没有这一页；配置自己的代理不受影响 |
| Agents 页（安装、更新、换版本） | 在 Mac 应用里实现 | 没有；agent 自己装，`doctor` 报告找到了什么（`agents-v0.md` §9 已这样写） |
| 局域网发现（Bonjour） | 由 Mac 应用发布 | 没有；靠配对载荷里的地址和 `/addresses`，和今天手机离开局域网时一样 |
| 终端样式 | 读 iTerm2 的配置 | 读不到就是默认样式，已是这样 |
| 配置的浏览器用的 `open` 垫片 | 垫的是 `/usr/bin/open` | Linux 上要垫 `xdg-open`（`BROWSER` 那一半已通用） |
| 保护规则 | `~/.agentswitch`、`~/.secret-gate` 按名字已覆盖；`Library`、数据卷那几条是 Mac 的 | 要逐条在 Linux 上试（§8） |
| 文案 | `on this Mac`、`chosen on the Mac` 这类写死的句子 | 要改成不分主机种类的说法 |

### 4.5 凭据网关放在哪个账户下

Mac 上网关跑在独立的服务账户里（`gate-service-v0.md`）：登录用户的进程——包括 agent——在文件层面读不到私钥。Linux 上有两档：

- **同用户**：网关由看护进程以登录用户身份起，密钥在 `~/.secret-gate`（0700）。agent 读不到它只靠各家的禁读规则，这是 Mac 在 2026-09-27 之前的状态。不需要 root。
- **独立账户**：`sudo agentswitch gate system-install` 建一个不能登录的系统用户，网关作为 systemd 系统服务在它名下运行，目录与接口照 `gate-service-v0.md`（`/var/lib/agentswitch/gate` 0700、`gate-public` 里是 CA 证书、公钥和按对端 uid 放行的套接字）。要一次 root，与 Mac 上输一次管理员密码相当。

建议：两档都做，安装时问；有 sudo 就用独立账户。服务器上 agent 更常以自动或跳过权限的方式跑，文件层面的隔离比在 Mac 上更要紧。先后上可以先同用户（已验证），独立账户作为后一步。

### 4.6 在没有浏览器的机器上登录 agent

AgentSwitch 不搬运登录：每台主机上的 agent 各自登录，凭据留在 agent 自己的地方。按各家的说明，无头机器上都能在终端里完成（打印网址，在别的设备上登录，把码贴回来；或填密钥）。配合已有的“没登录的配置开终端就从登录开始”，在手机或 Mac 上新建一个终端就能把登录做完：终端里出网址，在手边的设备上打开，登录后把码贴回终端。没验证（§8）。

### 4.7 地址与监听

- **地址**：今天配对载荷和 `/addresses` 的 `lan` 把 Docker 网桥也列了进去（10-04 那台机器上 11 个里 10 个是）。Linux 上按网卡过滤（`docker0`、`br-*`、`veth*`、`virbr*`），默认路由所在的网卡排最前。
- **来源限制照旧**：只接受私网、链路本地、Tailscale 网段。所以**只有公网地址的云主机必须走 Tailscale 或别的私网**，这是要的效果（没有公网可达面）。这类机器上监听最好只绑 Tailscale 的地址（今天是 `::` 全绑、连上来再按来源掐断）：`agentswitch host listen tailscale | private | all`。
- **不想装 Tailscale 时**：`ssh -L 4713:127.0.0.1:4713 <主机>`，使用端连本机的 4713。证书照样钉着指纹，来源是回环地址，在允许范围内；主机这边不用改，使用端要能手填一个地址。只对电脑上的使用端有用。
- 使用端连主机不走任何代理（系统代理、Clash、凭据网关的代理都不走）。

## 5. 使用端

### 5.1 iPhone：几台主机同时在线

今天的样子（代码里看到的）：可以配多台，同一时间只连一台；主机按证书指纹区分；整个应用只有一个 `AppModel`，里面一条连接、一个接口客户端，界面有 61 处直接读它；切换主机时停掉连接、清空取来的一切再重连。连接用的零件（钉指纹的会话、选地址、接口客户端）本来就是按主机传参的，不是全局的。Dispatch 标题里已经有一个切换主机的菜单（配了一台以上才出现）。任务、终端、会话、标签页的编号都只在各自主机内唯一，手机上的草稿、折叠状态、终端看法是按光秃秃的编号或路径存的。没有后台运行、没有推送、没有本地通知；实时活动只有一条，只在应用在前台时更新。

由此，分两步：

1. **Linux 主机先当“又一台”**。今天的切换就够用。要改的是：按 `GET /host` 换说法和图标（`Mac` 的文案有一百来处，标识符和 `macs.json` 这些内部名字不必动）、路径缩写用主机报的 `home`、没有的栏目不显示（`Mac App` 更新、Clash）、“移除”时请主机吊销自己。
2. **同时在线**。建议的形状是**按主机分开看、提醒汇总**，不合并列表：
   - 每台配了对的主机各有一个轻的看守：一条连接，定时问一个摘要。摘要用 `GET /live`——Mac 菜单栏卡片今天每秒问的那个，内容是进行中的任务、在干活或等你的终端、可以直接回答的请求——把它放进远程路由表（只读，里面的东西手机本来都读得到）。
   - 四个页仍然只显示“当前主机”，切换菜单从 Dispatch 的标题扩到每一页，菜单里每台主机带状态（有几个在等你）。
   - 等你的东西跨主机汇总：角标、提示音、实时活动都算上所有主机；每一行带主机名，点进去先切到那台主机再打开。实时活动的链接要带上主机（今天是 `agentswitch://terminal/<编号>`，没有主机）。
   - 手机上按编号、路径存的东西改成按“主机指纹 + 编号”存。
   - 不合并列表的理由：没有一个列表元素带着主机，编号会撞，文件夹树的键是各主机自己的路径；合并要动的面比分开看大得多，而“哪台在等我”这件最要紧的事，汇总提醒已经给了。
   - 应用在后台时仍然什么都收不到（没有推送），和今天一样。

### 5.2 Mac 主窗口：用别的主机

今天的样子（代码里看到的）：主窗口只有一个客户端 `DaemonClient`，地址写死 `http://127.0.0.1:<端口>`，凭 `local-token`；应用里没有钉证书的代码，也没有“主机”这个概念。只有 Dispatch 页隔着接口（`DispatchService`，它的注释里就写着留给“远处的 Mac”），Browser 页隔了一半，Terminals、Clash、设置、菜单栏卡片都直接拿这个客户端。好在两点：各页拿客户端的方式是“每次现取”，换一个来源就都跟着换；远程口对放行的路由是原样转给本地接口的，路径和数据形状完全相同——**同一个客户端换个地址、换成钉指纹的连接和设备令牌，就能对着别的主机用**，不必另写一套。

- **入口**：主窗口左上角的主机菜单（演示页第 2 节）：`This Mac` 加已配对的主机，各带状态；换主机时用“换台”那段转场（`dispatch-v0.md` 里说过，这个转场就是留给它的）。
- **配对**：`Settings › Hosts`（新的一栏）里粘贴配对链接，或输码加比对指纹（§2.2）。同一栏分两块：`This Mac Uses`（这台 Mac 作为使用端连着的主机）和 `Uses This Mac`（现在的 `Devices`）。
- **每一页连别的主机时**：

| 页 | 已经有远程路由的 | 不能照搬的 |
|---|---|---|
| Dispatch | 对话、任务、审批与提问、话题、上传、搜索 | 设置里 Dispatch 那一组（记忆、平台经验、MCP、skill、路由日志）不在远程表里，连别的主机时不显示：那是主机自己的管理 |
| Terminals | 列表、新建、恢复、画面流、简略视图、回复、权限卡、模型与档位、git 状态 | 终端屏幕上打字走的是 `/write`（每 4 毫秒一批原样按键），不在远程表里：不放开的话真终端只能看，回话只能用简略视图的回复框（§10 第 4 条）。拖进来的文件、回复里的附件今天给的是本机路径，改成上传；选文件夹用的是本机的面板，改成从主机用过的文件夹里选或手输；⌘ 点路径是在本机磁盘上找，连别的主机时不做 |
| Browser | Mac 上本来就有两种看法：真窗口，和画面流（主机报 `windows: false` 时用，与手机相同）。连别的主机一律用画面流，是现成的 | `Show Window`、静态预览、引擎安装不在远程表里，也不该在 |
| Clash | 路由都在远程表里 | 对面有 `clash` 才显示；“交给 Clash Verge”那一步只能在对面那台 Mac 上点 |
| Settings | — | 仍然是这台 Mac 自己的，只多 `Hosts` 一栏；配置的建、删、改颜色、模型设置、审批策略都是主机本机的事 |

- **连接怎么做**（建议界面直连；另一种做法见 §10 第 5 条）：`DaemonClient` 改成可以指向任意主机——本机是回环地址加 `local-token`，别的主机是 `https` 加钉指纹加设备令牌。钉指纹、选地址（局域网、Tailscale，断了重选）、解析配对链接、换令牌这几样，iPhone 的 `AgentSwitchKit` 里已有。两个应用是两个 package，约定是跨 package 只走进程和网络接口，所以这几个文件在 Mac 应用里照着各写一份（量小），不为它改约定。本机专有的事（看护、配对与设备、菜单栏卡片、各项设置）继续用本机的客户端。
- **给别的主机造密文**用那台主机的公钥。主窗口今天的“新建密文”用的是本机网关（`GateCLI`）；连别的主机时用内置的 secret-gate 对指定公钥封装（要给它加一个参数），不在 Swift 里做密码学。
- **顺手要改的小处**：
  - 屏幕编号是 `mac-<随机>`，服务把别的以 `mac` 开头的编号当成“这台 Mac 自己的另一块屏、已经松手”。第二台 Mac 的屏幕会被这样误读，编号要带上设备。
  - 远程口对表外的路由回带 `error` 的 404，应用今天把这种 404 读成“终端没了”；要分开。
  - 路径缩写、字体：路径按主机报的 `home` 缩；终端样式里的字体在本机找不到时用默认的。
- **跨主机的提醒**：菜单栏卡片今天只显示本机的。连着别的主机时把它们等你的东西也列进来（各带主机名），做法同手机（各主机问 `GET /live`）。

### 5.3 命令行当使用端（以后）

`agentswitch attach <主机> <终端>`：在任意一个真终端里接上服务持有的终端。对本机今天就有意义（在 iTerm 里接上 AgentSwitch 开的会话），对别的主机就是命令行使用端。它的令牌是一个 0600 的文件，必须在禁读名单里（§2.4）。不在这一轮。

## 6. 安全边界的变化

实现时写进 `packages/secret-gate/BOUNDARY.md` 和 `app-v0.md` §6：

1. **配对的设备等于能在主机上以用户身份跑命令**（经终端里的 agent）。对手机一直如此；现在电脑也能当使用端，所以电脑上保存的别的主机的令牌要防这台电脑自己的 agent（§2.4）。
2. **密文不跨主机。** 每台主机有自己的网关和密钥对，使用端给哪台主机发密文就用哪台的公钥；A 的密文在 B 解不开。手机存的密文已经按主机指纹标记，只在给它造的那台主机上列出。凭据不随连接扩散。
3. **服务不去连别的主机**（§0；若选了 §10 第 5 条的另一种做法，这一条要重写）：没有中转、没有跨主机调度，daemon 不保管也不使用别的主机的令牌。
4. **只输配对码时必须比对指纹**（§2.2）。
5. **无头主机的管理面是 SSH**：远程接口不加管理路由；`pair`、吊销、策略、配置的建删都要先登上那台机器。
6. **公网机器**：来源限制不变；监听最好只绑私网地址（§4.7）。
7. **Linux 上网关的隔离档位**要写清楚：同用户档下私钥只靠禁读规则挡着（§4.5）。
8. **原样按键、无头主机上的跳过权限模式**：定了以后各记一条（§10）。

## 7. 不做

- 信任组。
- 中转：手机够不着的主机，不经另一台主机转过去。走 Tailscale 或别的私网；电脑上还可以用 SSH 隧道（§4.7）。真要做有两种做法：只转字节（使用端与目标主机之间仍是端到端的钉指纹连接，中间那台看不到内容，但手机端要自己实现隧道里的 HTTP）；或中间那台用自己的令牌代发（简单，但等于“能连中间那台的人都能用它连着的所有主机”）。都先不做。
- 跨主机调度（A 的调度把任务派给 B 的 agent）：密文绑在各自网关的公钥上，另一台解不开；“使用对方的 Dispatch”指的是直接对 B 说话。
- 把会话从一台主机搬到另一台：会话是那台主机上 agent 自己的文件，换机器接着干用 agent 自己的办法和 git。
- 在 Linux 上替你装 agent、管版本（Agents 页）；Linux 上的 Clash。
- 按设备分权限档（§2.3）。

## 10. 待拍板

1. **Linux 无头版先只当主机**（建议），命令行使用端以后再说；还是一开始就要它两头都当。
2. **无头主机怎么管**：只经 SSH 加命令行（建议，远程接口不加管理路由）；还是也要能从 Mac 或手机上管（那就得有一档“管理员设备”）。
3. **无头主机上的跳过权限模式**：今天只有主机本机能选。无头主机的本机就是命令行，等于远程永远选不了。建议：主机上一个默认关着的开关（`agentswitch policy remote-bypass on`），打开后配对的设备才可以选。还是一律不许。
4. **Mac 当使用端时的键盘**：建议让远程口接受原样按键（`/write`），由主机上的开关管，默认开。理由：Mac 的终端屏幕就是靠它打字的，不放开真终端只能看；而文字入口今天已经能打任何命令再回车，只给文字并不减少配对设备能做的事。实现时要逐个 agent 确认没有哪个按键能把它切进跳过权限模式。还是照手机，只给文字和指定按键（演示页当初的建议）。
5. **Mac 怎么连别的主机**，两种做法：
   - **界面直连**（建议）：主窗口自己用钉指纹的连接去连，和手机一样；别的主机的令牌由应用保管。服务不出门，信任关系最简单。
   - **经本机服务转发**：主窗口仍然只连本机，本机的 daemon 加一段 `/hosts/<主机>/…` 转给对面。好处是命令行和网页控制台顺带也能用别的主机，菜单栏卡片的汇总在服务里做；手机经这台 Mac 去够它够不着的主机（中转）也几乎是白送的。代价是 daemon 开始保管别的主机的令牌并替人转发——agent 打交道的那个进程多了一块出站的面，而且“白送的中转”正是 §7 说先不做的那种信任扩大（能连这台 Mac 的设备，都能用它连着的主机）。
6. **Linux 上的凭据网关**：两档都做、安装时问、有 sudo 就用独立账户（建议）；还是只做同用户。
7. **两个使用端都“按主机分开看、提醒汇总”**（建议）；还是合并成一张列表。
8. **不做中转**（建议，靠 Tailscale 或 SSH 隧道）；还是有手机够不着、又不想装 Tailscale 的主机。
9. **安装形态**：一个按架构的压缩包加安装脚本、systemd 用户服务（建议）。以后可以加“从 Mac 上经 SSH 装到一台 Linux 并顺手配对”（配对载荷经 SSH 拿，不用扫码），要不要。
10. **先后**（§9）。
