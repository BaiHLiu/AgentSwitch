# 文件 v0：主窗口右侧的文件栏，手机上的同一套（2026-10-16，草案）

> 状态：设计稿，未写代码。演示页 `docs/design/concepts/files.html`（两种外观、Mac 与手机，几个可点的状态）。代码等用户看过说“做吧”。

用户（2026-10-16）：我想要给agentswitch加一个简单的文件管理功能，加到右边的侧边栏，像素风格用不一样的更适合展示文件的目录树结构，经典风格用更适合展示文件的文件夹结构，它的层级是在所有agent之上的，但是要做成右边栏的结构，从左边可以选择某个项目作为跳转接口，比如我在左边选择一个目录（或者目录下的一个项目）右键可以打开该目录的文件管理入口，然后第一次打开的时候默认打开家目录；也可以对当前打开的一个窗口加一个图标，便捷打开当前窗口所在的目录的文件管理（多窗口的时候就用多窗口的顶栏上加一个图标，单窗口的时候用app的顶栏上的图标，当然多窗口的时候app顶栏的图标也生效，就像是现在的终端/简略窗口切换一样）；文件管理的功能你找找有什么实现规范没有，可以先做个概念出来，要求目录树、列出文件、选中文件给agent、绝对目录层级展示（并且每一层都可点）、文件预览（没想好怎么做，iPhone和mac上实现应该不一样）。

## 0. 要点

- **`Files`：主窗口自己的一栏，在右边。** 它属于窗口，不属于哪个终端：换终端、换页、分屏、合屏它都还在，显示的是同一个位置。宽度可拖（默认 300 点，240–560），可收起；开没开、宽度、位置、展开了哪些文件夹，按节点各记各的。
- **两种外观各有自己的默认看法**：像素外观是**目录树**（`tree` 命令那种 `├─ └─ │` 字符画，等宽，一棵树里一层层展开）；经典外观是**文件夹**（Finder / iOS“文件”那种：一次一层，文件夹图标加 `›`，点进去换一层，`‹ ›` 前进后退）。`⋯` 菜单里两种都能换（`As Tree` / `As Folders`），记在这一台设备上。
- **绝对路径，每一层可点**：栏顶一行是当前文件夹的完整路径（`/ Users / you / Projects / lumen /`），点哪一层就到哪一层；太长时中间收成 `…`，点开是被收起的那几层。
- **入口**：
  - 左边列表里文件夹、终端、会话的右键菜单多一项 `Show in Files`：到那个文件夹（终端是它此刻所在的文件夹）。
  - 顶栏右边一个文件夹图标：到焦点那一块的文件夹；分屏时每块的标题栏上也有一个，到那一块的——和现在顶栏与标题栏上的终端 / 简略切换同一个排法。图标亮着表示文件栏正显示这一块的文件夹，再点一下收起。
  - 第一次打开在家目录，之后回到上次的位置。快捷键 `⌘⇧F`（同顶栏的图标）。
- **选中给 agent**：选一个或几个（⌘ 点、⇧ 点），`Add to Reply`、或拖到某一块上——落进那一块的回复框，是光标处的 `[File #n]` 占位符，和今天拖文件、`+` › `Files…` 是同一条路（发送时输入路径，文件不拷贝）；终端视图里拖上去照旧是输入路径。文件夹给的也是路径。
- **预览**：Mac 上选中一个文件，栏的下半是它的预览（文字、代码、图片、PDF 都由系统的 Quick Look 画；`空格` 放大成 Quick Look 的面板）。手机上点一个文件推进一页：文字由应用自己显示前 64 KB，图片、PDF 和其他交给系统的 `QLPreviewController`（先下载，上限 25 MB）。
- **只读**（第一版）：列目录、看信息、预览、给 agent、`Show in Finder`、`Copy Path`、`New Terminal Here`。不新建、不改名、不删除——这些在 Finder 里做（§9）。
- **服务给数据**：列目录、取信息、取预览都经服务的接口（`/files…`，§7），所以手机和别的节点用的是同一份；凭据所在的地方（与 `protected.ts` 同一张表）列出来只有名字和锁，不能打开、预览、给 agent。

## 1. 查到的规范，用了什么

| 来源 | 说的 | 这里怎么用 |
|---|---|---|
| Apple HIG · Path controls | 显示所选文件或文件夹的路径；标准样式是“磁盘、上层文件夹、所选项”一串，每项带图标和名字，放不下时**隐去首尾之间的名字**；放在窗口内容里，不放工具栏或状态栏（Finder 的路径栏在窗口内容的底部） | 路径行放在文件栏内容的顶上（不进顶栏、状态栏）；经典外观照标准样式画（图标 + 名字 + `›`）；放不下时首尾留着、中间收成 `…` 菜单 |
| Apple HIG · Outline views | 层级数据放在一列；文件夹点三角只展开它自己，⌥ 点展开全部子文件夹；**记住用户展开到哪一层**；长名字用中间省略号；可以排序、可以有搜索框 | 像素的树：`▸ ▾` 只展开 / 收起，⌥ 点展开全部；展开状态按节点记住；名字中间省略（`very-long-…-name.ts`） |
| Apple HIG · Column views | 层级深、经常在层与层之间来回时用分栏；第一栏是根；**选中没有下层的项时显示它的信息与预览**（Finder 的预览栏） | 经典的“文件夹”看法一次一层，根在路径行最左；选中文件时下半显示信息与预览——同 Finder 分栏的最后一栏，竖着放进窄的一栏里 |
| Apple HIG · Sidebars、Split views | 窗口变窄时可自动收起侧栏；给显示 / 隐藏的按钮或菜单命令和快捷键；**不要默认藏起来**；分隔线用 1 点细线，拖动改大小，设合理的最小最大宽度；重要的东西不放在侧栏最底下 | 顶栏的文件夹图标、`⌘⇧F`、`View` 菜单三处都能开关；1 点分隔线可拖，240–560 点；窗口窄到页面不足 520 点时，文件栏浮在页面上（§2）。默认关着——这一条和“不要默认藏起来”相反，理由：主窗口首先是终端，右边常驻一栏会压窄终端的列数；第一次用的人从左边右键或顶栏图标进来（§10 待定） |
| Apple HIG · File management | 自定义的文件浏览器要“顺着系统的文件系统”：打开时显示最相关的位置，但让人能去别的地方；用 Quick Look 预览自己打不开的文件；默认隐藏扩展名 | 打开时在最相关的位置（这一块的文件夹，没有就上次的，第一次是家目录），路径能一直点到 `/`；预览一律交给 Quick Look。**扩展名不隐藏**：给 agent 的是路径，开发者要看扩展名（与 Finder 默认不同，§10） |
| Apple · Quick Look（`QLPreviewView`、`QLPreviewPanel`、iOS `QLPreviewController`） | 系统画各种文件的预览；Mac 上可以嵌在自己的界面里，空格开面板；iOS 上是整页的控制器，要的是本地文件 | Mac：栏的下半嵌 `QLPreviewView`，空格开 `QLPreviewPanel`（Finder 的同一个手势）；iPhone：下载到应用的临时目录再交给 `QLPreviewController` |
| iOS “文件”App、`UIDocumentBrowserViewController` | 一次一层往下钻，导航栏标题是当前文件夹，**长按返回键列出上面各层**；列表 / 图标两种看法 | 手机上两种外观都是一次一层往下钻（像素的那一层仍画成树线，可就地展开一层，§5）；导航栏下面一行路径可点，长按返回键照系统列出各层 |
| WAI-ARIA APG · Tree View | ↓↑ 移动不展开；→ 展开，已展开时到第一个子项；← 收起，已收起时到上一层；Home / End；**按字母跳到下一个以它开头的项**；`*` 展开同层全部；多选：空格切换、⇧↓↑ 连选、⌃A 全选（Mac 上是 ⌘A）；`role=tree / treeitem / group`、`aria-expanded`、`aria-selected`、`aria-level` | 键盘照它做（§3.4）；网页版（控制台）照它标角色；原生用 `NSOutlineView` / SwiftUI `OutlineGroup` 自带的无障碍 |
| VS Code Explorer | 文件夹在前；`Reveal in Explorer`（从编辑器跳到它在树里的位置）、`Copy Path` / `Copy Relative Path`、`Reveal in Finder`、`Open in Integrated Terminal`；拖文件到聊天框或终端变成引用 / 路径；`.gitignore` 里的、`node_modules` 淡一档 | 文件夹在前；右键 `Copy Path`、`Copy Relative Path`（相对于这一块终端的文件夹）、`Show in Finder`、`New Terminal Here`；拖到回复框是占位符、拖到终端是路径；`.git`、`node_modules` 和隐藏文件淡一档 |
| `tree` 命令 | `├── └── │` 画树，文件夹名后不加符号（`-F` 时加 `/`），`-a` 才列隐藏文件 | 像素的树用左边列表已有的两格树线 `├─ └─ │`（ui-v0 §7.2 第 1 条），文件夹名后加 `/`（同 `tree -F` 与 `ls -F`），隐藏文件默认不列 |

## 2. 位置与层级（Mac）

- **一栏，在窗口右边，在顶栏与状态栏之间。** 顶栏和状态栏仍横跨整个窗口（dispatch-v0 §1、`bars.html` C）；左边是图标栏和页面自己的列表，中间是页面，右边是文件栏。文件栏和页面之间一条 1 点实线，可拖。按 `bars.html` 的规矩：有文件栏时这条线和顶栏、状态栏的线一起画完整，收起时不留线。
- **它是窗口的，不是页面的**：四页（Dispatch、Terminals、Browser、Clash）换来换去它都在；只有“给 agent”要看当前页有没有回复框（§4）。单独开出去的终端窗口（`item-window.html`）没有文件栏；那里的 `Show in Files` 把主窗口带到前面再打开。
- **和记录的右侧栏（`RecordSidePane`）**：那一栏在一块的里面、只说这个会话（上下文、任务清单、改过的文件）；文件栏在所有块的外面。两个可以同时开；文件栏一开，块变窄，块不够 980 点时记录的右侧栏照它自己的规矩不出（simple-view-v0 §5.2）。
- **窗口窄的时候**：打开文件栏后页面剩不到 520 点，文件栏改为浮在页面右边（1 点墨色框和抖动的硬阴影 / 经典是圆角和投影），不再挤页面；`esc` 或点页面收起。窗口拉宽后回到一栏。
- **记什么**：开没开、宽度、看法（树 / 文件夹）、显示隐藏文件与否、排序、每个位置展开过的文件夹、最近去过的位置，按节点分开记在应用偏好里（同 mesh-v0 §9“每个节点记住自己的终端布局”）。

## 3. 文件栏里有什么

从上到下：标题行、路径行、列表、底部（没选中时一行计数；选中了是预览）。

### 3.1 标题行

- 左：`// Files`（像素）/ `Files`（经典）；窗口在别的节点上时后面跟 `@ Mac mini`（信号色，同顶栏）。
- 右三个按钮：`⌂` 回家目录（`⌘⇧H`）；`⋯` 菜单（`As Tree` / `As Folders`、`Show Hidden Files ⌘⇧.`、`Sort By ›` 名字 / 修改时间 / 大小 / 类型、`Go to Folder… ⌘⇧G`、`Places ›`）；`×` 收起（`×` 只表示关闭，ui-v0 §7.2 第 4 条）。
- `Places`：家目录、各个终端此刻所在的文件夹（左边列表里有的）、最近去过的五个。左边列表本身就是项目的入口，这里只补“跳过去”的近路，不做第二套收藏。

### 3.2 路径行

- 当前文件夹的绝对路径，从 `/` 开始，每一层是一个按钮；最后一层（当前）墨色，前面的次一档。像素：`/ Users / you / Projects / lumen /`，等宽，悬停反色；经典：照 Path control 的标准样式，每层是文件夹图标加名字，层与层之间 `›`，悬停圆角底；最左的磁盘（`/`）只画图标，悬停写 `Macintosh HD`，左边 `‹ ›` 后退前进。
- 点一层：那一层成为当前文件夹（树以它为根 / 文件夹看法换到那一层）。右键一层：`Copy Path`、`Show in Finder`、`New Terminal Here`。
- 放不下时：首（`/`）尾（当前和它的上一层）留着，中间收成 `…`，点开是一串被收起的层（Path control 的做法）。
- 家目录写全路径（`/Users/you`），不缩成 `~`：用户要的是“绝对目录层级”。别处（列表、标题）照旧用 `~`（ui-v0 §1 第 5 条）。

### 3.3 列表

- **像素 · 树**（默认）：当前文件夹的内容，一行一项：树线、`▸ / ▾`（只有文件夹有）、名字（文件夹加 `/`）、右边淡色的大小与修改时间（`2.1K` `10/14` `Today 13:02`；栏宽不到 300 点时只留时间）。文件夹在前，各自按名字。点 `▸` 展开一层（⌥ 点展开全部子文件夹）；点名字选中；双击文件夹（或 `↩`）把它当作新的当前文件夹；双击文件是 `Open`（交给它的默认程序）。最上面一行 `../` 到上一层。
- **经典 · 文件夹**（默认）：一次一层，Finder 列表那种：类型图标（文件夹是强调色的线条文件夹）、名字、右边次要色的修改时间和大小；文件夹行尾一个 `›`。单击选中，双击或点 `›` 进去；路径行左边 `‹ ›` 后退前进（`⌘[` `⌘]`）。
- **两种看法共同的**：
  - 选中：像素是行左 3 点信号色竖条加浅一档的底（同左边列表）；经典是圆角的强调色底。多选 ⌘ 点、⇧ 点、`⌘A`。
  - 隐藏文件（`.` 开头）默认不列；`⋯` › `Show Hidden Files`（`⌘⇧.`，Finder 的键）。列出时与 `.git`、`node_modules` 一样淡一档。
  - 受保护的地方（§7.3）照列，名字后一把锁，淡一档；选不中、点不开、拖不走，悬停说明“此处存放 AgentSwitch 的凭据，无法在此打开。”。
  - 符号链接：名字后 `→ 目标`（淡色）；进去或预览时按目标的实际位置判断能不能打开。
  - 一个文件夹超过 2000 项：先列 2000 项，末尾一行 `▸ 1,240 More`。
  - 读不了的文件夹（系统没给 AgentSwitch 访问权限，macOS 的“文件与文件夹”）：一行说明“AgentSwitch 无权访问此文件夹。可在“系统设置 › 隐私与安全性 › 文件与文件夹”中允许。”，`Open System Settings`。第一次读“桌面”“文稿”“下载”时系统会在 Mac 上问一次；从手机读时手机上写“Mac 上正在询问是否允许 AgentSwitch 访问此文件夹。”。
  - 文件变了：当前文件夹每 3 秒看一次修改时间（与终端列表同一个节奏），变了就重读这一层；没在看的不读。
- **右键一项**：`Add to Reply`、`Quick Look`（空格）、`Open`、`Show in Finder`、`Copy Path`（`⌥⌘C`，Finder 的键）、`Copy Relative Path`（相对于焦点那一块终端的文件夹；不在它下面时变灰）；文件夹另有 `Open as Current Folder`、`New Terminal Here`。

### 3.4 键盘（焦点在列表里时）

- `↓ ↑` 移动；`→` 展开 / 到第一个子项，`←` 收起 / 到上一层（树）；经典看法里 `→` 等于进去、`←` 等于后退一层（`⌘↓` `⌘↑` 同 Finder）。
- `Home` `End`；打字跳到以它开头的下一项（APG typeahead）；`*` 展开同层全部（树）。
- `空格` Quick Look；`↩` 打开文件夹 / 文件（与 Finder 的“↩ 改名”不同：第一版没有改名）；`⌥↩` `Add to Reply`（不用 `⌘↩`：终端页的确认卡用它，§10 待定）。
- `⌘⇧H` 家目录、`⌘⇧G` 去某个文件夹、`⌘⇧.` 隐藏文件、`esc` 回到页面（焦点还给那一块）。

### 3.5 预览（Mac）

- 选中一个文件，列表下面分出预览（默认占栏高的 45%，中间的线可拖，拖到底就关掉预览、记住）：
  - 第一行：名字；第二行：`TypeScript · 2.1 KB · Today 13:02`（类型、大小、修改时间；文字文件加行数）。
  - 内容：本机的文件直接用 `QLPreviewView` 画（文字、代码、Markdown、图片、PDF、音视频、Office 文件都由系统处理）；别的节点上的文件由服务给预览（§7），文字等宽显示前 64 KB，图片显示服务做的缩略图，其余只写信息。
  - 一排按钮：`Add to Reply`（主）、`Open`、`Show in Finder`。
- 选中几个：预览处写 `3 Items · 24 KB` 和同一排按钮。
- 选中一个文件夹：写它的项数与修改时间，按钮是 `Add to Reply`、`Open as Current Folder`、`New Terminal Here`。
- `空格`：Quick Look 的面板（`QLPreviewPanel`），和在 Finder 里按空格一样；方向键在面板里换上一个、下一个。
- 预览只在用户选中时取；滚动列表不取。

## 4. 给 agent

- **落到哪**：焦点那一块的回复框（简略视图），是光标处的 `[File #n]` 占位符，回复框上面多一个带文件名的小条和 `×`——和今天拖文件进来、`+` › `Files…` 完全一样（simple-view-v0 §5.1“回复带文件”）：发送时服务在占位符处输入路径（空格和 shell 的特殊字符前加反斜杠），**文件不拷贝**；Claude Code 和 Codex 见到图片的路径就当图片附上。一次至多 10 个（同现在）。
- **三种做法**：`Add to Reply`（按钮、右键、`⌥↩`）；拖一项或几项到某一块上（落到那一块，不一定是焦点那块）；拖到回复框的某个位置（插在那里）。
- **终端视图**：那一块没有回复框；`Add to Reply` 和拖上去都是把路径打进终端的光标处（与从 Finder 拖进终端一样），不回车。
- **文件夹**：给的是它的路径，占位符也是 `[File #n]`（小条上是文件夹图标）。
- **Dispatch 页**：落进 Dispatch 的输入框，作为这条任务的附件（路径）。
- **Browser、Clash 页**：没有回复框，`Add to Reply` 变灰，悬停说明“此页没有回复框。”。
- **别的节点**：窗口在别的节点上时，文件栏列的是那个节点的文件，给那个节点上的 agent 的就是那边的路径——不用上传（今天别的节点的回复附件要上传，mesh-v0 §5.2）。
- **不能给的**：受保护的地方（§7.3）。选中里混着它们时按钮变灰并说明。

## 5. iPhone

- **入口**：
  - 终端页 `+` 菜单多一项 `Files on Mac`（图标 `laptopcomputer`；`Files` 加 `folder` 已经是“从手机的文件 App 选”，一个图标一个意思）——打开在这个终端此刻所在的文件夹，从这里选的落进这个终端的回复框。
  - 终端列表导航栏一个文件夹按钮——打开在上次的位置（第一次家目录），这时没有“给哪个终端”，只有 `Copy Path`、`Share…`。
  - 终端行长按菜单 `Show in Files`。
- **样子**：一张大的 sheet（`large` 档），里面是一摞页（`NavigationStack`）：
  - 导航栏：标题是当前文件夹的名字，右边 `Select`，左边 `Done`；长按返回键是系统列出的上面各层。
  - 导航栏下一行路径（`/ Users / you / Projects /`），横向可以滑，每层可点。
  - 列表：经典是 iOS“文件”的列表（文件夹图标、名字、第二行时间与大小、`›`）；像素是树线画的这一层（`├─ src/ ▸`），点 `▸` 就地展开一层，点名字进去——手机屏窄，深的树不好看，所以树只就地展开、往深处还是进页。
- **预览**：点一个文件推进一页。
  - 文字（按类型和内容判断）：应用自己显示前 64 KB，等宽、可横向滑、行号（像素）；末尾 `Load More`。
  - 图片：服务给的缩略图先出，可放大；`Open Preview` 下载原图交给 `QLPreviewController`。
  - PDF 和其他：`Open Preview`：下载（进度条）后交给 `QLPreviewController`；超过 25 MB 的不下载，只写信息和“文件超过 25 MB，未下载。”。
  - 底部：`Add to Reply`（从终端来的时候）、`Copy Path`。
- **给 agent**：在预览页 `Add to Reply`，或在列表里 `Select` 勾几项 → 底栏 `Add to Reply (2)`；回到终端页，回复框光标处是 `[File #1] [File #2]`，上面一排小条（文件名和 `on Mac`）。发送时附件是 `{path}`，不是上传（§7.2）。
- **受保护的、读不了的**：同 Mac（锁、说明）。

## 6. 和别的设计的关系

- **terminal-v0 / simple-view-v0**：回复框的附件、占位符、发送时输入路径，原样用；新加的只有“文件来自服务列出的路径”这一种来源（手机：`{path}` 附件）。
- **mesh-v0**：文件栏跟着窗口的节点走（顶栏的节点选择）；每个节点记自己的位置；`/files…` 进远程表（§7.4）。
- **profiles-v0**：与配置无关；文件栏读的是服务所在账户能读的东西。
- **ui-v0 §7 / §8**：像素用字符、树线、`▸ ▾`、`[ Add to Reply ]`；经典用系统字体、线条图标、圆角、强调色。演示页里两种都画了。

## 7. 服务

### 7.1 接口（草案）

都是 GET、只读，路径一律是绝对路径（`~` 由服务展开）；本机的应用经本地令牌，手机和别的节点经远程表。

| 接口 | 给什么 |
|---|---|
| `GET /files?path=<abs>&hidden=0\|1&limit=2000` | 一层：`{path, parent, home, entries: [{name, kind: dir\|file\|link\|other, size, mtime, hidden, dim?, locked?, link?: {target, kind}}], more}`；不给 `path` 时是家目录 |
| `GET /files/stat?path=<abs>` | 一项：同上的字段，加 `type`（`text` `image` `pdf` `audio` `video` `archive` `binary`，按扩展名和前 8 KB 判断：有 NUL 或不是 UTF-8 就不当文字）、文字的行数（读到 256 KB 为止）、文件夹的项数 |
| `GET /files/preview?path=<abs>` | 文字：前 64 KB（`{text, truncated, lines}`）；图片：缩略图（Mac 上用系统的 `sips` / Quick Look 缩略图做，长边 512 像素，JPEG）；其他：只给 `stat` |
| `GET /files/content?path=<abs>` | 原样的字节，支持 `Range`；超过上限（手机 25 MB）回 413。给手机的 Quick Look、别的节点上的文件的 Quick Look 用 |

`/terminals/:id/input` 的 `attachments` 多一种 `{path}`：服务检查路径存在、不在受保护的地方，再按占位符输入这个路径（与 `{token, upload}` 搬进附件目录后输入路径，是同一个后半段）。

### 7.2 本机的应用怎么用

- 列表、信息经服务（手机、别的节点、本机走同一份代码和同一张保护表）。
- 本机文件的预览：应用拿到路径后直接交给 Quick Look 画（应用和服务是同一个用户，读得到；这样不用把字节经服务转一遍）。受保护的不交。
- 别的节点上的文件：文字和图片用 `/files/preview`；要 Quick Look 时 `/files/content` 下到应用的临时目录（随应用退出删掉）。

### 7.3 安全边界

- **只读**：第一版没有写的接口。
- **受保护的地方**：与调度执行器的读禁区同一张表（`protected.ts` 的 `defaultProtected().readDenied`：凭据网关的目录与 socket、浏览器会话档案与共用浏览器的状态目录、远程监听的 TLS 目录、本地令牌、节点目录）。在里面或就是它：列出时只有名字和 `locked`，没有大小、时间、内容；`stat`、`preview`、`content`、`{path}` 附件一律 403。终端里的禁区表更宽松（`terminalProtected`，只关网关和节点），这里不用它：文件栏会把内容送到手机上。
- **先求真实位置再判断**：每个路径 `realpath` 之后再对表；符号链接按目标判断，指向禁区的链接照“受保护”显示；`..` 和相对路径不收。
- **远程调用**（手机、别的节点）：`/files…` 加进远程表；`content` 有大小上限；每次远程读文件内容记一行审计（设备、路径、字节数，**不记内容**）。日志里只有路径。
- **凭据不进执行器**：文件栏给 agent 的只是路径；agent 读不读得到由它自己的禁区决定（调度执行器、终端各按各的表），这里不替它打开任何东西。
- **系统的访问权限**：服务以登录用户运行，读“桌面”“文稿”“下载”、外置盘、网络盘时 macOS 会对 AgentSwitch 问一次（TCC）；拒绝后回 `{error: "permission"}`，界面照 §3.3 说明。
- 改这些入口时同步更新 `packages/secret-gate/BOUNDARY.md`（文件内容第一次经服务到手机）。

### 7.4 别的节点

- 窗口在别的节点上时，文件栏的请求发给那个节点（远程表里的同一组 `/files…`）；Linux 节点没有 Quick Look 缩略图，图片的 `preview` 退回原图（≤ 5 MB）或只给信息。
- 手机连着几个节点时（mesh-v0 §5.1），`Files on Mac` 用的是这个终端所在的那个节点。

## 8. 演示页

`docs/design/concepts/files.html`：
- 一个 Mac 主窗口（图标栏、左边的终端列表、一块或两块、右边的文件栏、状态栏），七个状态：第一次打开（家目录）、从左边右键进入一个项目、从分屏标题栏的图标进入那一块的文件夹、选中文件看预览、选两个给 agent（回复框里出现 `[File #1] [File #2]`）、空格的 Quick Look、窗口窄时浮起来的文件栏。树里的行、路径的每一层、`⌂`、`⋯` 里的看法与隐藏文件都能点。

- 两种外观、深浅色可切。示例的路径和文件都是编的（家目录 `/Users/you`）。

## 9. 分步（拍板以后）

1. **第一步（最小可用）**：服务的 `/files`、`/files/stat`、`/files/preview`、`/files/content` 与保护规则、`{path}` 附件、测试（禁区、链接、相对路径、超大文件夹、二进制判断、远程上限）；Mac 的文件栏（两种看法、路径行、预览、Quick Look、`Add to Reply` 与拖放、右键菜单、键盘、记住状态）与三个入口（左边右键、顶栏图标、标题栏图标）；手机的 sheet（入口、往下钻、路径、预览、`Add to Reply`）。
2. **第二步**：别的节点（§7.4）；文件后面标 git 的改动（`M` `A` `?`，左边列表已经有每个文件夹的 git）——“把改过的文件给 agent”会常用；当前文件夹里按名字筛选；`Follow Pane`（焦点换到哪一块，文件栏跟到哪一块的文件夹，VS Code 的 auto reveal）。
3. **以后再说**：新建文件夹、改名、移到废纸篓；从手机往 Mac 的某个文件夹传文件；`Open With`。用户要的是“简单的”，这些在 Finder 里做。

## 10. 待拍板

1. **默认开还是关**：HIG 说侧栏不要默认藏起来；这一稿默认关（终端要宽度），第一次从入口打开以后记住开着。要不要第一次启动就开着？
2. **快捷键**：`⌘⇧F` 开关（同顶栏图标）、`⌥↩` `Add to Reply`、`⌘⇧H` `⌘⇧G` `⌘⇧.` `⌥⌘C` 照 Finder。`⌘⇧F` 在 Finder 里是“最近使用”，在 VS Code 里是全局搜索，这里都不冲突；要不要换？
3. **经典的“文件夹”看法**：这一稿一次一层（同 iOS 与 Finder 的列表）。栏拉宽（≥ 460 点）时要不要变成 Finder 的分栏（上一层 | 这一层）？
4. **扩展名与隐藏文件**：扩展名一律显示（与 Finder 默认相反）；隐藏文件默认不列。`.env` 这类可能有密码的文件，要不要在给手机预览前提醒一句？（它们不在 AgentSwitch 的禁区里，Finder 和终端都能看。）更要紧的是各家的登录文件和钥匙：`~/.ssh/`、`~/.codex/auth.json`、`~/.aws/credentials`、各配置自己的登录目录。它们也不在禁区里，经文件栏预览到手机上，内容就离开了这台 Mac。是把这些常见位置加进文件栏自己的禁区（只列名字和锁），还是只在手机上预览前提醒？
5. **手机的入口**：这一稿是终端页 `+` 菜单、终端列表导航栏、行长按三处，没有单独的标签页。要不要第五个标签 `Files`？
6. **远程读文件的开关**：手机、别的节点读这台 Mac 的文件内容，要不要像“远程打字”那样有一个节点自己的开关（默认开）？
7. **预览的位置**：栏的下半（这一稿）还是只在空格时弹出 Quick Look？下半会让列表变矮。
