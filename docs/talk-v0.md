# 讨论 v0：几个 agent 在 AgentSwitch 里互相说话（2026-10-15，草案）

> 状态：设计稿，未写代码。演示页 `docs/design/concepts/talk.html`（待拍板的几件在页顶是开关；两种外观也是一个开关，§5 末尾）。2026-10-15 用真的 Codex 和 Claude Code 做过一次试验（§9）：页上的两个讨论是它们真实的对话，§2.1、§4.2、§4.8 按其中“设计评审”那一场达成的一致改过。代码等用户看过说“做吧”。

用户（2026-10-15）：我想写一个 多agent交流机制，要求是各个agent通用、只在agentswitch里可以用、删掉agentswitch不留下多余的插件、mcp等垃圾、可以可视化。

## 0. 要点

- **讨论（Room）**：你建一个讨论，把几个终端拉进去；同一个讨论里的终端可以互相说话，不在同一个讨论里的互不相通。默认谁也不连谁。
- **消息由服务转交**。服务里有一份讨论的记录（谁对谁说了什么、送到没有）；一条消息由服务**当成一句新的话打进对方的终端**——四个 agent 都是服务持有的终端，这一步不靠任何一家的特性，所以通用。
- **说话有两条路**：
  1. 终端启动时临时挂上的三个工具（`peers`、`send`、`read`），用来主动找人、点名说话；
  2. **一轮由讨论里的话引起，这一轮的回答自动带回讨论**，交给说话的那一位。没有工具的 agent、开讨论以前就在跑的终端，靠这一条也能参加。
- **不留东西**：工具和说明只在启动那一次带上（与终端里的浏览器工具同一条路，`terminals/launch.ts`），不写任何一家 agent 的用户配置；讨论的记录在服务自己的库里。删掉 AgentSwitch，剩下的只有各家会话记录里的对话本身。
- **看得见**：主窗口新的一页 `Rooms`：聊天式（谁对谁说了什么）与泳道式（每个成员一条线、消息是箭头，看谁在等谁）两种看法；终端里收到、发出的话画成单独的卡；一个讨论停下来等你时，实时活动和菜单栏卡片上有它。手机上同一页。
- **护栏**：连续若干轮没有你说话就停下来问你；别的 agent 的话不是你的话（不能替你批准、不在对方等你时送进去、不会被当成命令）；消息里不许有明文凭据。

## 2. 概念

- **讨论（Room）**：名字、成员、记录、状态（进行中 / 停下等你 / 已结束）、停下的门槛（§4.4）。属于这台 Mac 的服务。
- **成员**：这台 Mac 上的终端（以后：别的节点上的终端、调度的任务）。在讨论里的称呼就是终端在列表里的编号加 agent，例如 `05 · Codex`；配置的颜色照旧标在旁边。**一个终端同时只在一个讨论里**（v0；这样 `send` 不用说发往哪个讨论）。你自己也是成员，叫 `You`。
- **消息**：谁说的、对谁（某一位或全体）、正文（Markdown）、时间、第几跳（§4.4）、每位收件人那里送到没有（排队 / 已送到 / 跳过）。
- **一轮**：一条消息被送进某个终端、那个 agent 因此做了一轮。停下的门槛按“没有你介入的轮数”算。

### 2.1 已有的会话怎么拉进来（2026-10-15，用户：如果是现有的session，我想拉两个进来讨论呢？）

讨论的成员是 AgentSwitch 持有的终端；已有的会话按它此刻在哪，分四种。都在“新建讨论”里列出来（§5），也可以在 Terminals 列表里多选几行（终端、会话都行）→ 右键 `New Room With These…`。

| 会话此刻 | 拉进来时 | 进来以后 |
|---|---|---|
| 开在 AgentSwitch 的终端里，终端是这个功能有了以后开的 | 直接加入 | 有工具，也收话、回答带回 |
| 开在 AgentSwitch 的终端里，终端开在这个功能以前（或应用更新以前） | 直接加入；另有一个选项 `Reopen With Tools`：等它空闲，服务退出这个 agent、在同一个终端里用同一个会话重开（Claude Code `--resume`、Codex `resume`、OpenCode `--session`、pi 续接），这次带上工具。对话不丢（同一份会话记录），丢的是进程里的东西：后台在跑的命令、shell 的状态、没存的输入；在做时不重开，等它停 | 不选：没有工具，靠收话与回答带回参加（§0 第 2 条路）；选了：同第一行 |
| 没开着，只在列表里（历史会话） | 建讨论时由服务续接（`POST /terminals/resume`，同列表里的 `Resume`），开一个新终端，带着工具 | 同第一行；它带着自己原来的上下文进来，这正是拉已有会话的用处 |
| 开在别的程序里（iTerm、ChatGPT 的 Codex……，terminal-v0 §5 查得到的那几家） | 拉不进来：服务不持有它，两个进程同写一份会话会乱（terminal-v0 §5 只许一个写）。行上写“开在 iTerm2 里”，可以选 `Fork`：分叉一份（新会话带着完整历史），分叉出来的那份在 AgentSwitch 的终端里进讨论，原来那个不动；或者先在那边退出再勾它 | 分叉出来的那份同第一行 |

`Reopen With Tools` 怎么重开（试验里两位评审定的，§9）：现在做不到——`POST /terminals/resume` 遇到同一个会话直接返回已有的终端，`host.spawn()` 只会新开终端。要加一个原位的 `restart(id)`：保留终端号、`sent`、讨论成员身份、配置、权限方式与模型；结束整个进程组（`kill()` 按 `-pid`），用它的会话号续接；和“每个终端一个 C 持有进程”（terminal-v0，d9c408c）共用同一条启动路径，不另起一套。启动参数不另存一份：配置里的代理地址可能带口令，存一份就在进程里多一份明文，出口也可能已经变了——把 `start()` 里由配置号求出 home、key、出口的那段（`api/terminals.ts`）抽成一个函数，重开时按配置号重新求一遍；配置已删或代理不通就不重开，说明原因。模型取 `modelNow ?? model`，思考强度取会话记录里的当前值（`TerminalInfo.effort` 只是启动时的），权限取 AgentSwitch 自己的 `mode`（不取 agent 屏幕上的 `modeNow`）。hook 的令牌要换新：`Session` 里它现在是只读的，要改成能换。

拉进来不会自动替你说话：进讨论这件事不打进它的终端；第一句由你说（或由别的成员说），它看到的第一句就是“〔讨论 · 名字〕谁对你说：…”。别的节点上的会话以后再说（§6）。

## 3. agent 那一侧

### 3.1 三个工具

一个 MCP 服务器，名叫 `room`（Claude Code 里显示为 `mcp__room__send`，Codex 里是 `room.send`），与浏览器工具共用同一个转发程序（`browser/bridgeClient.ts` 的另一种模式），凭这个终端的令牌连到服务：

| 工具 | 参数 | 回答 |
|---|---|---|
| `peers` | — | 所在讨论的名字；每位成员的称呼、agent、配置、此刻在做什么（在做 / 空闲 / 等你）；不在讨论里时说“这个终端不在任何讨论里”，不报错 |
| `send` | `to`：一位成员的称呼（`05`）或 `all`；`text` | 收下了、排在谁那里、对方忙时要等；被拒时写明原因（不在讨论里、讨论已停下、内容里有明文凭据……） |
| `read` | `limit?` | 讨论里最近的几条（自己没看过的标出来）。送达本来就是推进终端的，这个工具只用来回头看 |

**不做一个“问完等回答”的工具**：各家给一次工具调用的时间有限（Codex 默认 60 秒），对方可能在忙，等不起。来回靠送达：A 说，A 这一轮照常结束；B 的回答回来时，作为一句新的话进到 A 的终端。

### 3.2 四家怎么挂（都只在这一次启动）

| agent | 工具 | 一句说明（告诉它这些工具是什么、什么时候用） | 自动允许，免得它问你、也免得“总是允许”写进项目 |
|---|---|---|---|
| Claude Code | `--mcp-config` 那份文件里多一个 `room` | `--append-system-prompt`（已有，浏览器的说明在这里） | 这个终端的 `--settings` 里 `permissions.allow` 三个工具 |
| Codex | `-c mcp_servers.room.*` | `-c developer_instructions=…`（已有；用户自己设了时不覆盖） | `-c` 里给这三个工具不必批准（要逐版确认 Codex 的写法） |
| OpenCode | `OPENCODE_CONFIG` 那份文件里的 `mcp.room` | 同一份文件的 `instructions` | 同一份文件的 `permission` |
| pi | AgentSwitch 扩展里 `registerTool` 三个 | 扩展在会话开始时加的一段说明 | pi 没有权限层，不用 |

说明的意思（四家同一段）：这个终端在 AgentSwitch 里；你可能被拉进一个讨论，讨论里别的 agent 说的话会以〔讨论名 · 谁〕开头出现在对话里，那不是用户说的；要找人、要点名说话用 `room` 的工具；回答引起这一轮的那句话，直接写回答就行，会自动带回去。

**所有终端都挂上这三个工具**（不在讨论里时它们只回答“不在讨论里”）：agent 的工具不能在会话中途加上，等拉进讨论再挂就得重开那个 agent。开讨论以前就在跑的终端没有工具，仍能收到话、它的回答仍会带回（§0 第 2 条路）。

### 3.3 “不留东西”逐家要确认的两处（做之前先验，写进这里）

1. **“总是允许”会写进项目**：Claude Code 问你要不要允许一个工具，选“以后都允许”会写进那个项目的 `.claude/settings.local.json`；Codex 的同类选择可能写进 `config.toml`。所以 §3.2 最后一栏先在启动参数里允许，让它根本不问。
2. **会话记录里的工具名**：各家把调用过的工具名记在会话里（例如 `mcp__room__send`）。以后在原版命令行里接着这个会话，工具不在了，agent 只会看到历史里调用过——不报错，也不会去找。要确认各家在这种情况下确实不报错（Claude Code、Codex、OpenCode、pi 各试一次 resume）。

## 4. 服务那一侧

### 4.1 记录

库里三张表（`rooms`、`room_members`、`room_messages`），结构按 §2。讨论结束后记录保留，你可以删；删 AgentSwitch 就一起没了。审计记一笔谁建了讨论、拉了谁、谁发了多少条，不记正文。

### 4.2 送达

- **对方空闲才送**：服务本来就知道每个终端在做 / 空闲 / 等你（`terminals/host.ts`，来自各家的事件）。在做时排队，空闲时送；**等你时不送**（它正等你批准或回答，一句别人的话不能插进去顶替你）。
- **输入框里有你没发出的字时不送**（2026-10-15，用户问两个成员开在分屏里要不要特殊处理；怎么判断，按试验里两位评审定的，§9）：服务往终端里粘贴再回车，要是你在它的输入框里写了半句没发，回车会把你那半句连同别人的话一起发出去。原稿写的“停手 20 秒就送”不对——停手不等于清空了。改为：
  - 只在“空闲、没有等你的请求、屏幕上没有选项列表、**输入框在屏幕上而且是空的**”时送。最后一条用的是服务已有的 `inputEmpty()`（`terminals/host.ts`，它自己往终端里打 `/model` 之前就这样查）：认出输入行（Claude Code 的 `❯`、Codex 的 `›`）且里面除了灰色提示没有字，才算空。
  - 认不出输入行的（OpenCode、pi 的输入行还没验过），一直排着，不强送；排队那张卡上写明在等什么，给一个 `Open Terminal`（去那边处理），不给“强制发送”——那正是会把话拼进你草稿的那一下。
  - 另外记下“这个终端的输入框动过”：所有往里写东西的入口都算（`/write`、`/keys`、不提交的 `/input`、`/attach`），只盯一处会漏；回车才清掉这个记号，但屏幕上有选项列表时的回车是在选择，不算发出。这个记号只能让服务**更早停手**，不能让它在读不出屏幕时放行。
  - 排着时，终端那一块的标题栏写 `1 Queued · You're Typing`；简略视图的回复框是应用自己的，草稿不在终端里，不受影响。
- **排着的几条合成一次送**：对方忙完时有三条在等，就作为一句话送进去，各条分开写，免得它连做三轮。
- **送进去的样子**：

  ```
  〔讨论 · 登录重构〕05 · Codex 对你说：
  登录页的跳转我改在 src/auth/redirect.ts 了，你那边的测试要按新地址改。
  ```

  第一行以〔开头：不会被当成 `/` 命令、`!` 命令或别的特殊输入；整段按回复框的方式粘贴（终端要了 bracketed paste 就整段贴，再回车），中间的换行不会提前把话发出去。
- **回答自动带回**：一轮是由讨论里的话引起的，这一轮结束时 agent 的最后一段回答（简略视图读得到，`sessions/record.ts`）作为一条消息交给说话的那一位；这一轮里它已经用 `send` 说过话，就不再自动带。你可以在讨论里关掉这一条（只靠工具说话）。

### 4.3 你也在讨论里

你在 `Rooms` 页的输入框里说的话同样送给某一位或全体，算“你介入了”（§4.4 重新数）。你在某个成员的终端里直接打字（终端视图或简略视图的回复框）不进讨论：那句话不发给别的成员，那一轮的回答也不自动带回——它是在回答你，不是在回答讨论；但它算“你在场”，§4.4 的轮数重新数。

### 4.4 停下

- **连续 N 轮没有你的话就停下**：讨论的状态变成“停下等你”，排着的消息不再送；`Rooms` 页、实时活动、菜单栏卡片上出现一张卡：`这个讨论已经连续 8 轮没有你的消息，先停下了。` `[ Continue ]`（再给 N 轮）`[ End Room ]`。N 默认 8，建讨论时可改，可以选“不停”。
- **跳数**：一条由另一条的回答引起，跳数加一；同一条话在两位之间来回超过 N 跳，同样停下。防两位互相客套、无限来回。
- **成员的终端退出**：讨论里写一行“07 · Claude Code 已结束”；发给它的消息标为跳过。

### 4.5 提醒

由讨论里的话引起的一轮，结束时不单独提醒（实时活动、菜单栏卡片、声音都不响）：两个 agent 来回说十轮，就会响十次，而那不是你交代的事。只有讨论本身要你的时候才提醒：停下等你（§4.4）、有成员等你批准或回答（它自己的确认卡照旧）、有 agent 请求拉人（§8 第 1 条选了时）。你直接交代给某个成员的那一轮，照旧提醒。

### 4.6 权限与凭据

- **别的 agent 的话不是你的话**：只作为对话里的一句话送进去，不能回答对方等你的批准或提问（等你时不送，§4.2），收到的一方照它自己的权限模式办事。说明里也告诉它这一点（§3.2）。
- **不许明文凭据**：消息入库前过一次检查（与 `maskSecrets` 同一套识别：密钥形状、token 前缀、长的随机串）；像凭据的就拒收，`send` 的回答写明“不要在讨论里传密码或 token”。终端不在凭据网关后面（profiles-v0 §8），密文在终端里解不开，所以不是封成密文，而是拒收。CLAUDE.md 的规矩：库和日志里只有密文。
- **只在同一个讨论里**：`send` 只能发给同一讨论的成员；`peers` 只列同一讨论的成员。工具看不到别的终端，也不能把谁拉进讨论（拉人是你的事，见 §8 第 1 条）。

### 4.7 接口

本地接口（Mac 的窗口、命令行、网页控制台）与远程口（手机、别的节点）同一套：

- `GET /rooms`、`POST /rooms {name, members, stopAfter?, autoReturn?}`、`PATCH /rooms/:id`（改名、加人、去人、`stopAfter`、`autoReturn`、`continue`、`end`）、`DELETE /rooms/:id`
- `GET /rooms/:id/messages?after=`、`POST /rooms/:id/messages {to, text}`（你说的话）、`GET /rooms/:id/events`（SSE：新消息、送达、成员状态）
- 工具那一路：`POST /rooms/tool {tool, args}`，只认终端的令牌，只对这个终端所在的讨论

命令行：`agentswitch rooms`、`rooms new <名字> <终端…>`、`rooms say <讨论> [@成员] <话>`、`rooms watch <讨论>`——Linux 节点就靠它看讨论。

### 4.8 哪一轮是讨论引起的（试验里两位评审补的，§9）

要画讨论卡、判断“由讨论引起”、自动带回、不重复，就得知道一轮的起因。现在的发送链路没有这些：`/input` 只有 `text`/`submit`，`SentReply`、终端事件、`onWorkDone()` 都不带讨论或消息的号。做法：

- 讨论的投递走服务内部的一条路（不是 `/input`），带上讨论号和消息号；`SentReply` 加 `messageIds`（几条合成一次送时共用一条），`confirmSent()` 在记录里认出它时，把它记为这一轮的起因。
- 一轮结束（`turnEnded()`）发出 `{terminalId, turnId, cause}`。这一轮里你自己也往这个终端送过话（Claude Code 忙时可以排队），回答就不自动带回——它也在回答你。
- 取回答要等结束之后的那一版记录（`turnEnded()` 可能早于记录里出现最后一段回答）：从起因那句话到下一句用户话之间，最后一段回答。等不到就把这条标成“未取到”，不猜。
- OpenCode 的终端，`watchRecord()` 现在直接跳过（读的是它的库，没有记录版本号）：一轮结束后有限次重读，同样超时标“未取到”。

## 5. 界面（演示页 `concepts/talk.html`）

- **主窗口 `Rooms` 页**（图标栏在 Clash 前面多一个图标：几个点连着线）：
  - 左栏：讨论列表，每个写名字、成员的 agent 标记、状态（进行中转圈 / 停下等你琥珀色 / 已结束灰）；`New Room`。
  - 中间，聊天看法：每条消息一张卡，抬头 `05 · Codex → 07 · Claude Code` 和时间，正文是 Markdown；自动带回的回答写 `Reply`；你说的话靠右；系统的话是一行小字（谁加入、谁结束、停下了）。排队还没送的消息虚线框、写“等 07 忙完”。
  - 中间，泳道看法（右上角 `Chat` / `Lanes`）：每位成员一条竖线（顶上是称呼和状态），在做的时段是实的、空闲是细的、等你是琥珀色；一条消息是一根从说话人到收件人的箭头，排队中的是虚线；点一根箭头，右边显示那条消息。用来看谁在等谁、在哪里绕圈。
  - 右栏：成员（状态、配置颜色、`Open Terminal`、`Remove`），讨论的设置（停下门槛、回答自动带回）。
  - 底部输入框：`对全体说… ` 或用 `@05` 点名。
- **新建讨论**：在 Terminals 列表里选几行（终端或历史会话）→ 右键 `New Room With These…`；或在 `Rooms` 页 `New Room` 里勾选。面板分两组：`Terminals`（开着的；没挂工具的那一行带 `Reopen With Tools` 的勾选）和 `Sessions`（没开着的，最近的在上，按文件夹可搜；勾上的在建讨论时续接；开在别的程序里的那一行灰着，写明在哪，旁边一个 `Fork`）。名字默认取第一个成员的标题。（§2.1）
- **终端里**：简略视图里，收到的话不画成你的气泡，而是一张讨论卡（〔登录重构〕`05 · Codex`，点一下去 `Rooms` 页那一条）；`send` 在工作那一行里写成 `Sent to 07 · Claude Code`。终端视图里就是 agent 自己画的那一句。终端列表里，讨论里的终端行尾多一个小标记，悬停写讨论名。
- **两个成员开在分屏里**（Terminals 页）：不用特殊处理也能用——每块看的就是自己的终端。为了看得清谁在跟谁说：
  - 每块的标题栏写上所在讨论（小标记加讨论名，点一下去 `Rooms` 页），和最近一次讨论里的往来：收到的写 `← 05 · 14:14`，发出的写 `→ 07 · Reply`，排着的写 `1 Queued`；你在这一块打字、讨论的话排着时写 `1 Queued · You're Typing`（§4.2）。
  - 送达时不抢焦点、不切块、不滚走你在看的地方：哪一块是焦点照旧是你的；简略视图在末尾的跟着到末尾，不在末尾的不动（同 simple-view-v0 §5.2 的规则）。
  - `Rooms` 页的成员栏有 `Open Side by Side`：把讨论的成员（最多四个，Terminals 页最多四块）摆进分屏，各自开在你上次用的看法（终端视图或简略视图）。
  - 目录树里，讨论成员那几行行尾带讨论名（已有，§5 终端里那一条）。
- **停下等你**：讨论卡上和实时活动里都有 `[ Continue ]` `[ End Room ]`。
- **手机**：`Terminals` 标签顶上多一个 `Rooms` 入口；讨论页是聊天看法（不画泳道），底部同样的输入框，停下卡同样两个按钮。
- **两种外观**（ui-v0 §7、§8；演示页顶上的“外观”开关）。布局、入口、文案的意思两种外观相同，只换画法：

  | | Pixel | Classic |
  |---|---|---|
  | 字 | 短词、抬头、时间用等宽字 | 一律系统字体；等宽字只留给代码、命令、路径和终端屏幕 |
  | 图标栏 | 像素图标，`Rooms` 是三个方块连着线；当前页左边一道粉线 | 线性图标（三个圆连着线，SF Symbols 里的那一类）；当前页是圆角高亮、图标取系统蓝 |
  | agent 标记 | 像素标记 | 线性写法（`✳`、`›_`、`▢`、`π`） |
  | 状态 | 方块：琥珀色闪 = 停下等你；盲文转圈 = 在做；灰方块 = 结束 | 圆点：橙色外圈慢慢呼吸 = 等你；系统转圈 = 在做；灰色空心圆 = 结束 |
  | 状态短词 | `Busy`、`Idle`、`Waiting`、`Ended`、`Gateway` | `Working`、`Ready`、`Needs You`、`Ended`、`Gateway OK`（ui-v0 §8 第 2 条） |
  | 消息卡 | 方角、细框；你说的话是凸起的方框；排队中虚线框 | 圆角卡片（比底亮一点）；你说的话是圆角气泡（墨色淡底）；排队中虚线圆角框 |
  | 停下卡、请求拉人卡 | 琥珀色 / 粉色的方框 | 琥珀色 / 系统蓝的淡底圆角框 |
  | 按钮 | `[ Continue ]`、`[ End Room ]`、`[ Send ]`；实时活动里小写 `[ continue ]` | 标准按钮：主按钮填系统蓝（`Continue`、`Send`、`Create`），`End Room` 红字 |
  | 小标题 | `// Members`、`// Room` | `Members`、`Room`（半粗、次要色） |
  | 新建讨论 | `[x]` 勾选、`[8]` 选中的门槛、`[x] On` | 系统的勾选框、分段控件、开关 |
  | 泳道 | 平头的线、实心箭头 | 圆头的线、线条箭头 |

  主窗口在经典外观里照旧是一个黑面（ui-v0 §8 第 3 条），卡片只比底亮一点；`Rooms` 页随系统深浅（与调度页一样）。终端视图里是 agent 自己画的，两种外观一样。

## 6. 不做的（v0）

- 调度的任务做成员（以后：执行器用同样的工具）；别的节点上的终端做成员（以后：消息经节点之间已有的连接）。
- 一个终端同时在几个讨论里。
- agent 自己建讨论、自己拉人（§8 第 1 条，等拍板）。
- 消息里带文件：同一台 Mac 上的 agent 写路径就够了。
- 讨论的内容拿去给路由器、摘要器读。

## 8. 待拍板

1. **谁建讨论**：只有你（建议，v0）／ agent 也可以请求拉人（`invite` 工具，每次弹卡等你批）。

5. **回答自动带回**：默认开（建议：不用工具也能参加）／默认关（只有 `send` 才算说话）。
6. **名字**：页名 `Rooms`、一个讨论叫 Room；或 `Talk`。

## 9. 试验（2026-10-15）

用户：画的太简略了，你应该弄几个真实的任务让他们交流一下，然后弄点真实渲染的图。

**做了什么**：`packages/daemon/scripts/room_trial.ts`（打真模型，不是测试）在跑着的 AgentSwitch 里开两个终端（`manual`：Codex 只读沙箱，Claude Code 改东西要问），把开场的话送给第一位，之后每段回答由脚本转给另一位，直到有人写 `[达成一致]` 或到 6 段。只做了设计里“送达”这一半：没有挂工具，`send` 由脚本代劳；它只在服务自己的判断都通过时打字（空闲、没有等你的请求、没有选项列表、`inputEmpty`——在从终端画面流还原的屏幕上算），没有替谁回答过任何问题。两件都是只读的真事，都在 AgentSwitch 仓库里（两家都信任过的只有这个文件夹，新文件夹会先问要不要信任，那是用户的事）：

**试验找出的问题**：

- **简略视图丢话**（已修，`sessions/jsonl.ts` `unwrapPastes`）：Claude Code 把整段粘贴进来的话存成 `<pasted_content id="…">…</pasted_content id="…">`，读记录时它被当成系统插进来的东西扔掉了——你粘贴一大段话，简略视图里就没有这句，列表的标题也跳过它。脚本因此在 Claude Code 的记录里找不到送进去的话、停了一次，改为按时间取回答后接着跑完。修好以后的读法读出了这四段会话里全部的话。
- 设计的三处（上面）。

**真实渲染**：演示页第 2 节的图是调试版应用画的（`-designPreview <目录> -designPreviewOnly room -roomData <目录>`，`RoomPreview`）：Terminals 页、两位各一块简略视图，内容是这两段会话真实的记录（用修好的读法读出），列表里只有这两个终端。终端视图不用应用出图：离屏出图画不出终端自己的底色（以前的预览图里也是白底），所以终端视图是终端画面流的真实快照，在演示页里按它的颜色画。页面的数据在 `docs/design/concepts/talk-data.js`，图在 `talk-media/`。

**没试到的**：工具（`peers`、`send`、`read`）和它们在各家的挂法、`room` 工具“总是允许”会不会写进项目（§3.3）；OpenCode、pi；停下的门槛、请求拉人、你在打字时排队——演示页上这些标着“示意”。权限请求碰到过一次：排查那一场里 Claude Code 要跑一条命令时停下来问（16:35），是用户在 iPhone 上批准的；脚本照规矩一直等着，没有替谁回答——§4.6 说的“别的 agent 的话不能替你批准”，在真的讨论里就是这样。
